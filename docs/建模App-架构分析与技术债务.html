一句话结论：这套 App 的“形”已经很专业（视口、隔离、笔刷、UV、历史都齐）， 但“骨”还是脚本级——单文件 UI、破坏式网格、O(面数) 的拾取与绘画、贴图以 base64 内联文档。 继续加功能的边际成本正在上升，而且已经在三个真实缺陷上付过利息。

01现状盘点

先看体积与分层。数字本身不是债，但“增长最快的文件承担了最多职责”是。

275 / 42该文件函数数 / 事件监听数
100 / 15index.html 的 script / stylesheet 标签
219探针断言（单一脚本 2,878 行）
层组成规模评价
数据内核 seed-mesh-core、seed-operators、seed-uv、seed-model-scene、seed-selection、seed-evaluator 等 11 个模块 5,041 行 边界基本干净，全部挂 window.SeedModel / SeedSelection；求值器是空壳。
外壳与交互 model-desk.js：视口渲染、相机、手柄、选择、UV 面板（壳）、导入导出、菜单与面板 DOM（绘画 / 隔离 / 历史 / ViewCube 已拆出） 6,484 行 仍承担多项职责；onClick 一个函数（L5310 起）覆盖几十种动作。
样式 css/12-modeldesk.css 等 15 份，按原行号切片 7,347 行 文件头自述“按原始行号连续切片，靠 link 顺序维持层叠”——新增样式随时可能被后加载文件覆盖。
旧 3D 栈 model3d、m3d-slots、model-document、texpaint、texbrush、uvpack 等 11 个 9,868 行 仍在为“模型库 / 贴图”面板服务，与新栈并行存在：两套网格、两套画笔、两套文档。
验证 tools/probe-modeldesk.js（Playwright + Edge） 2,878 行 行为覆盖很强，但无内核单测、无 CI、依赖固定 waitForTimeout。

分层示意

model-desk.js（外壳 / 交互 / 渲染 / 历史 / IO） → SeedCommands、SeedTools → SeedSelection、SeedModel.UV → SeedModel.Mesh、SeedModel.Operators → SeedModel.Scene → 文档（GLB / 资产桥）。方向是对的；问题是第一层太厚，把本该属于数据层的 “UV 角号语义、渲染拆点映射、贴图编码”都吸了进来。

逐项对照，而不是笼统地说“还差得远”。差异集中在五处，其余是量的问题。

能力Blender / Maya / Max 的做法本仓库现状差距性质

03技术债务清单

按“继续拖会怎样”排序，不按“改起来爽不爽”排序。每条都给出证据位置。

P0D1外壳单文件化：6,484 行（原 8,364 行）承载多项职责
证据
model-desk.js：275 个函数、42 处 addEventListener、巨型 innerHTML 模板；单一 st 对象集中视口、选择、软选择、UV、绘画、隔离、历史、面板状态。已拆出 md-isolate.js（140）、md-paint.js（354）、md-uv-editor.js（1,652）、md-history.js（189）、md-viewcube.js（242）。
影响
任何改动都要在 6 千行里找落点；无法单测 UI 逻辑；__debug() 把内部状态直接交给探针，测试与实现互相锁定。
建议
继续把剩余职责拆开：Viewport（renderer/camera/quad）、Overlays（边/点/手柄）、Panels（右栏/左栏/菜单）、DocIO（打开/保存/内容浏览器）；动作统一走 SeedCommands，DOM 只负责呈现。
P0D2破坏式建模：没有可回放的构造历史
证据
seed-evaluator.js 全文 42 行，只有接口；seed-operators.js（1,599 行）直接改写 mesh.positions / faceOffsets / rawIndices；文档只存“结果网格”。
影响
挤出后再想改厚度只能撤销重做；参数化、程序化、批量重构都无从谈起。对专业用户最直观的“不像专业软件”就来自这里。
建议
先做算子命令化：每个算子产出 {op, params, inputHashes}，节点持一条 op 链，Evaluator 从基网格重放；第一步只覆盖挤出/环切/倒角。历史从“文档快照”逐步换成“命令 + 快照兜底”。
P0D3实时路径 O(面数)：拾取、绘画、重建
证据
paintRayHit（L1422）每次指针移动逐三角求交；rebuildModel（L3087）每次编辑重建全部 pivot / 几何 / 材质；liveRefresh（L1143）每帧全量回写顶点并 computeVertexNormals。
影响
当前 1 万面级的资产还能撑；到 10 万面会明显掉帧，笔刷会“粘笔”，隔离改选一次要重算整套几何。
建议
静态网格建 BVH（射线与笔刷共用）；绘画只在笔刷包围盒内求交；变换/绘画走脏区提交，不重建整个 BufferGeometry；隔离改成 per-face visibility mask 或 drawRange，而不是生成替身网格。
P1D4三套索引隐式约定：顶点号 / UV 角号 / 渲染顶点号
证据
buildGeometry（L748）按 (顶点, UV) 拆渲染顶点，用 geo.userData.mdOrig 反查；rawIndices 语义在ensureRawIndices（L271）中曾从“顶点号”改为“角号”。
影响
近期三个缺陷全部源于此：挤出后全身贴图错乱、拖面时整块炸开、平平涂没有贴图。每次都要靠读码+探针反推，而不是靠类型或不变量挡住。
建议
把三层写成一页契约：Vertex（共享空间点）、Corner（面角，承载 UV/法线/材质）、RenderVertex（GPU 拆点，仅渲染层可见）。内核只暴露 Corner/Vertex API，渲染层唯一持有映射；加“角号连续性 / UV 有限 / 渲染映射可逆”的不变量测试。
P1D5贴图以 base64 内联文档，历史按 PNG 计价
证据
textureDataURL（L6363）把贴图压成 ≤1024 JPEG 的 data URL 塞进 doc.materials.slotMaps；每笔绘画 canvas.toDataURL('image/png') 再存一份；HISTORY_BUDGET 64MB 按字符串字节计。
影响
文档膨胀、保存变慢、每笔画撤销成本是整张贴图；大贴图反复编解码还会掉精度（再导出 GLB 只剩降采样版本）。
建议
贴图移出文档：走已有的资源/资产桥（blob 引用 + 缩略图），文档只存 textureRef；历史存脏矩形而非整图；绘画按 mip/分块存储，避免每次全量 PNG。
P1D6材质模型过窄：4 个全局槽 + 单通道 baseColor
证据
materialsOf（L108）只归一化 slotNames / slotColors / slotMaps；slotMaps[slot] 是文档级共享，没有“对象材质实例”。
影响
做 PBR、粗糙度/法线绘制、把两个对象贴不同外观、UDIM、材质复制都受限；专业用户会立刻感到“只能涂色”。
建议
升级为材质 datablock（id + 通道）+ 节点引用 materialSlots（字段已存在，只是语义单薄）。先补 baseColor / normal / roughness 三通道，再谈节点。
P1D7双轨 3D 栈：新旧两套网格与画笔并存
证据
旧栈 11 个文件 9,868 行（model3d / m3d-* / texpaint / texbrush / uvpack …），新栈 11 个文件 5,041 行；两套都能编辑网格、都能画贴图。
影响
同一概念两份实现，修 bug 要修两遍；新人不知道哪套是“真相”；导出/导入路径互相踩。
建议
明确“seed-* 是唯一真相”，旧栈降为只读预览或直接下线；迁移调用点用清单管理，禁止新功能再进旧栈。
P2D8验证只有一条浏览器探针
证据
tools/probe-modeldesk.js 2,878 行、219 条断言、依赖 msedge 与固定等待；package.json 里没有对应脚本，.github/ 不存在。
影响
内核的纯数学部分（算子、UV、哈希）没有秒级回归；探针一挂就是几十秒起，且失败点难定位。
建议
加 node 单测（不依赖 DOM）：算子输入输出、面积/水密/角号连续、UV 覆盖、渲染映射可逆；探针保留做集成验收。把 run 命令写进 package.json。
P2D9CSS 按行号切片，层叠靠加载顺序
证据
12-modeldesk.css 文件头自述：“按原始行号连续切片……靠 index.html 的 link 顺序维持层叠……别在 08 之前写最终样式”。
影响
新加样式可能被后面的文件静默覆盖；右栏那几轮布局改动都在和时间赛跑（本次「属性编辑器」页签就牵扯三处宽度断点）。
建议
把 modeldesk 相关样式收进一个文件，按区块（菜单/视口/右栏/浮层）分区，尺寸用 CSS 变量集中管理。
P2D10场景能力缺位：无层级、无实例、隔离靠替身
证据
node.parent 字段存在但未参与变换/可见性；applyIsolation（L2976）只按“当前激活对象”切 pivot.visible；组件隔离每次改选都重建一份子网格。
影响
多对象工程的整理成本高；隔离瞬时会多占一份几何内存；无法做“引用同一网格的多个实例”。
建议
补父子变换与组；隔离改为几何级 mask（同一条 geometry 上按面可见），这一项能直接抵掉 D3 的替身开销。
P2D11无构建、无 lint、全局命名空间
证据
index.html 里 100 个 <script src>、15 个样式表；模块全部挂 window.SeedModel 等全局；没有 ESLint 配置。
影响
启动解析成本、加载顺序耦合、拼写错误只能等运行时；重构（改名/搬文件）没有工具兜底。
建议
不必上打包器，但可换 ES Module（Electron 直接支持 file:// 的 module），或至少加 ESLint + tsc --allowJs --checkJs 的渐进类型检查。

04已经在收利息：三个近期缺陷的归因

债务不是理论。过去这段时间修的三个问题，全是 D4 / D3 / D2 的直接产物。

缺陷表象真实根因对应债务
挤出后全身贴图错乱 一挤出面，整只模型贴图乱飞 rawIndices 存的是顶点号，却被当成 UV 角号去索引 uvs D4
拖面时模型炸成尖刺 拖动组件手柄时网格自交、尖刺四射 渲染层按 (顶点, UV) 拆点后，实时刷新仍按下标直拷 positions，缓冲区错位 D3 + D4
画笔无法撤销 画完无法回退，历史里没有这一笔 历史只识别“文档差异”，贴图写入不在快照差分范围内 D2
规律：凡是“改了网格/贴图却看不见效果”的 bug，最后都落在三套索引或“结果 vs 过程”的边界上。 这意味着下一步不该继续加功能，而该先把这些边界写成代码契约和测试。

05演进路线（按投入产出排序）

不改架构目标，只改“先做什么”。每步都有明确的退出条件。

01
固化不变量（先止血）

把 Vertex / Corner / RenderVertex 三层写进内核注释与 API；补 node 单测：角号连续、UV 有限、渲染映射可逆、挤出侧壁 UV 继承、面积守恒。

退出条件：任何改动破坏索引约定时，单测在 1 秒内失败，而不是等探针截图。
02
拆外壳

从 model-desk.js 抽出 Viewport / Overlays / Panels / Paint / Isolate / UV / History / ViewCube / DocIO 模块；菜单、工具架、右栏按钮统一发 SeedCommands，DOM 只读状态。已完成 Isolate / Paint / UV / History / ViewCube（8,805 → 6,484 行），其余待拆。

退出条件：model-desk.js 降到 2,000 行以内；新增一个工具只需加命令 + 面板项，不改事件大循环。
03
实时路径加速

BVH（拾取与笔刷共用）→ 笔刷包围盒求交 → 变换/绘画脏区提交 → 隔离改 mask。四件事可以独立落地、独立验收。

退出条件：10 万面资产下拖拽与绘画仍保持交互帧率；隔离切换不再分配新几何。
04
资源化贴图与历史

贴图迁到 blob 引用（textureRef），文档不再内联 base64；历史记录脏矩形 + 操作类型，贴图按块计价。

退出条件：文档体积与“画了多少笔”脱钩；64MB 预算能容纳的笔画数提升一个量级。
05
构造历史（真正的“专业感”）

Evaluator 从空壳变成 op 链重放；先接管挤出/环切/倒角，其它算子保持烘焙；op 参数可再编辑。

退出条件：挤出后能改厚度而不撤销；文档里能看见一条可回放的算子链。

不建议现在做

① 重写成半边缘结构（收益大但会打断所有算子与探针，先用契约和测试锁住现有语义）； ② 引入前端框架重做 UI（当前问题是职责没切开，不是缺少组件库）； ③ 一次性替换 GLB 读写（先把贴图从文档里搬出去，再谈格式）。

报告依据：仓库当前快照（2026-11-05）。行号与规模均为实测： js/ 96 文件 58,119 行、css 7,347 行、model-desk.js 6,484 行 / 275 函数 / 42 监听、 probe 2,878 行 / 219 断言、seed-* 11 文件 5,041 行、旧 3D 栈 11 文件 9,868 行。 评分是工程判断，不是精确度量；债务条目均附可核对的文件与行号。

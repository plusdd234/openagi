## 1. 一句总纲（BV1kXnu6nEXg，这条最该背）

- 「AI 的工作就是一个**线性工作流，上游的生成错误会在下游不断累加**。比如说你生成的图上有错误，就会影响到模型生成上，然后再生成模型、贴图这几个环节下来，**错误被不断放大**。但是反过来说，**如果你把每个环节都抠到极致，就会有质的飞跃**。」
- 「我这个参考图不是模型，是我炼的参考图……实际生成的模型效果大概是这样，这个效果出来之后我自己也很震惊。」
- 「然后贴上图的效果大概是这样：不仅**外面完美贴合**，而且**内部的内衣都做出来了**。」

> **上游每个环节的误差都会在下游放大**，所以"事后修"永远不如"入口抠"。

## 2. 自研的贴图系统（以及为什么放弃）· BV1kXnu6nEXg

- 「本来我觉得 Tripo 的贴图幻觉太高了，所以我就想自己做一个贴图系统。这是我做了一大半的贴图系统，它的原理就是**直接根据模型上每个三角面的纹理坐标位置，直接从我的多视图参考上面去摘三角形，贴到模型上**，理论上可以**杜绝所有幻觉**。」
- 「但是后来为什么放弃呢？因为我发现**我给自己贴图系统做的一些预处理，放到 Tripo 或者 Meshy 里面，提升效果更大**，所以它现在就变成了我的**图像处理的一个工具**了。」
- 「由于我这个贴图工具**要求参考图跟模型网格严格对齐**，所以需要**先根据模型渲染出真正的多视图**，然后再把**深度和网格信息轰到多视图上**，用这个作为**轮廓和结构限制**，得到**像素级对应的纹理参考**。」
- 「这个模型我没敢做太多，因为做一次要我 **100 积分**。但就目前的效果其实是非常稳定的，毕竟**参考图已经练到极致**了。**理论上就算没 AI，纯靠摘三角面都可以做贴图**了。但是依旧会**受到遮挡的影响**，不过相对于之前，**幻觉率已经大幅度降低了**。」
- 「工具和流程都在群里公布了。如果懒得做也可以找我做，**收你 30 块**。」

**判读**：他自己的结论是"预处理比贴图更值钱"——**把力气花在"把参考图做到对齐"上，比花在"把贴图算法做到完美"上收益大**。

## 3. 「多级多角度正向投射技术」· BV1rdRTB8EvA

他自己强调「**这是我自己发明的一个名词**」，三个词各自对应一个做法：

| 词 | 做法 | 解决什么 |
|---|---|---|
| **多级** | 「纹理生成**并非整体生成**，而是采用**多种细分等级**。比如眼睛图案复杂，**单独把眼睛抠出来，在整体模型旁边放置，并给予更大的大小和分辨率**」 | 小面积高细节部位像素不够 |
| **多角度** | 「纹理投射**不是单一视角**，而是**在单张高分辨率的视图中一次性绘制多视图**，来**减少 AI 推测多视图时几何结构的幻觉**」 | 一张图里拼多个视角，AI 不必自己想象侧面 |
| **正向投射** | 「使用**生成后的模型截图作为正交视角**，让 AI **将纹理精准地绘制到正交视角的模型之上**，用**绝对的几何结构完全消除纹理映射的幻觉**」 | 生成图 ≠ 模型几何 → 靠"正交截图当画布" |

- 「我是基于之前视频中做出来的那个模型，**用选曲面的方式把眼睛部位单独复制了一份，放到了旁边**。这张图并不是（未生成）模型的设计图，而是**模型（已生成）之后的图案设计图**——让 AI 通过**已经生成后的模型的精准几何结构**给它对应的位置添加图案。在这之后进行纹理映射的时候，就可以**避免纹理映射的错位问题**。」

> **核心认知**：参考图不该是"原画"，而该是"**模型的正交截图 + 在截图旁边补细节**"。

### 3.1 为什么不在 Meshy 里画，非要用 UE（本篇最实用的对比）

- 「有人可能会问，为什么不用 Meshy 自带的纹理绘制功能？因为它那个**实在是太不好用了**：
  ① 你绘制完之后要**等它卡顿个两三秒**才可以把纹理投射上去；
  ② 它是**基于屏幕空间的绘制，而不是基于模型表面的绘制**；
  ③ 一个更重要的问题：**Meshy 只能编辑表面颜色，而修改不了其他通道的贴图**。」
- 「但是**虚幻引擎可以指定贴图进行绘制**，可以对图案的**亮度、饱和度等各种参数进行精细调整**，甚至还可以**自己编写材质**。最重要的是，它**展现出来的效果就是我们最终游戏产品中的效果，实现所见即所得**。」
- 「在未来，我们可能会使用**虚幻引擎来完成模型处理的最终阶段**，而不是在各种建模软件里面，因为在不同软件里面，模型的展现效果其实差别也是很大的。」

## 4. 二次元贴图的两条流程（一体 vs 拆解）· BV1A3t36kEmi

### 4.1 解决的问题

「这次主要针对的问题是 AI 生成的**杂色问题**以及**贴图色差问题**。可以看到我上的贴图**颜色非常的纯，没有任何杂色**、乱七八糟的手绘阴影。」

### 4.2 一体生成流程（用 Meshy）

- 「模型生成采用的是 **Meshy**……但用过 Meshy 的人都知道，他们家的模型**都特别软**，经常很多结构糊成一团。针对他的这种特性，**我给他定制了一套专门的参考图**——通过**在参考图像上生成模型的拓扑布线**，来**强化各种几何的体积**。」
- 「不同模型网站的训练数据不一样，所以**对参考图的胃口也不一样**：这种**糊脸纹理的彩色体块图**是给**混元**用的。」
- 「为了得到更纯的颜色，我们需要**将原画转化为一个手办图**：**手办图的结构要硬朗、体块要明显、颜色要单一**——就要 AI 看到你这个头发，才知道你这个整个头发都是**一个纯色**。」
- 「图二是一套**图集**，只有 Meshy 能这么干：Meshy 是**硬参考**——你传入的轮廓跟这个模型完全不一样，其实问题也不大。这个图集的作用主要是起到一个**纹理补充**的效果：比如在我的主视图里眼睛这个部位看起来特别小、像素不够，参考不足就容易糊，那么我在图集的其他位置补上这样的图，AI 就知道眼睛应该怎么画了。」
- 「只能用得起 **1K 的参考图**，所以通过这种方式**不需要 4K 参考也可以出很好的效果**。」

### 4.3 拆解流程（多部位分别生成）

- 「拆解流程就是那种感觉比较**中规中矩**的。说实话，我感觉**对原画的还原程度上没有一体的高**。它的原理就是**在参考图阶段就将它拆分成多部位零件**。」
- 「左边的就是生成模型的参考：通过**布线强化几何结构、色彩、区分体块和标记部位**，得到一个**更硬朗的模型**。」
- 「由于**部位拆分之后，模型与模型之间的遮挡变小、相互干扰变小**，所以可以**还原一些原画上面的风格化效果**，比如说**头发上的高光**，而且可以**很干净的颜色**，不会出现"头发被染上皮肤色"之类的现象。」
- 「它的**优点**就是**内存小、还原程度高**；**缺点**就是**还原度太高了，对你的参考图要求也就更高**——AI 不需要怎么思考，只需要复制你的参考图就行了。看这里我的原画下面**很细很细的描边**，在这里被**当做纹理的一部分给贴上去了**。所以你的**原画不能有一点的描边**。**原画的效果就要是最终的效果。**」
- 「模块化的部位连一连材质就可以直接看效果了。关键的需要**根据拓扑关系拆分组，然后再拼起来**。**只要你的头发跟脑袋是一锅出的，一般都能拼得像。**」
- 「这里看到它的**颜色偏亮**，这个是**虚幻自带的色调映射器**的问题。」
- 「**这一阶段是不用考虑面数和 UV 的**，因为这个**高模上的纹理是可以烘焙到低模上的**。」

## 5. UE 侧：模块化拆件 + 绑定（BV1pY9oBvEyt）

### 5.1 前置三件（照抄）

1. 「**导出虚幻引擎的小白人骨骼**，方便对齐人物尺寸和进行绑定——这样就可以**直接通用所有的虚幻引擎小白人的动作**。」
2. 「下载这个叫做 **modular enemy character** 的项目（虚幻引擎的模块化人物工程）。我们不会完全照着它来，但在那里有**各种模块化部位绑定示范**和**八个角色的基础模板**。」
3. 「你已经有了一套 **AI 生成的、拓扑好的模型**，可以**使用混元自动展一下 UV**。」

### 5.2 部位三分类（这是拆件判据）

| 类型 | 定义 | 例子 |
|---|---|---|
| **主骨骼** | 「跟人体身体是完全一整套的骨骼……用的是**人物完整的骨骼，也就是小白人的骨骼**」 | 脑袋、上身、手、下身、鞋子 |
| **附加骨骼** | 「**并不在人物的主骨骼之内，而是有一套自己的骨骼**；从头发开始的这段骨骼则是**通过插槽插在这个名叫 HD 的头骨上**」 | 头发、毛发、尾巴 |
| **无骨骼** | 「一些**静态装饰**，不会伴随着人体肌肉一起变形的」 | 头饰、眼镜 |

### 5.3 流程顺序

- 「**模块化拆分应当在拓扑之后、展开 UV 之前**。也就是说完整流程应当是：
  ① **高模生成** → ② **低模拓扑** → ③ **部位拆分** → ④ **UV 展开** → ⑤ **人物绑定** → ⑥ **纹理映射**。」

> **UV 展开的位置是关键**：他**绑定前**展 UV。**「岛选拆件」这条路只对"还没绑定"的资产成立**——绑好权重再拆件就要动拓扑，代价大。

### 5.4 绑定手法（UE 蒙皮权重，不用笔刷）

- 「首先**创建骨骼网格体时指定小白人的骨骼**，然后**调整骨骼位置、旋转和缩放**，让小白人骨骼和人物部位一致。」
- 「在这之后就可以用**虚幻引擎的蒙皮权重工具**。虚幻引擎的蒙皮权重工具和普通建模软件**很不一样**，它主要还是靠**选取点和选取骨骼**，通过**参数调整**来弄的。」
- 「我在绑定的时候**几乎不会使用笔刷绘制蒙皮**。第一是因为**笔刷绘制容易选不到内部点，很容易炸面**；第二是**程序化的计算更符合我的口味**，可能是因为我不是一个美术的原因。」
- 「由于现在我们的角色骨骼就是小白人骨骼了，因此**无需重定向就可以直接替换上去**，看游戏中的实际效果，然后**不断修改权重直到满意**。」
- 「其他模块化部位可以通过这个 **Set Leader Pose 节点**来将小白人的骨骼**传递给其他部位骨骼**。」

> 这条对程序化/agent 工作流是个**方法级提醒**：他用的是**数值化权重编辑（选点+选骨+参数运算）**——可脚本化、可复现，比笔刷更适合自动化。注意：UE 的权重工具是**引擎侧**，救完要回导。

## 6. 五篇串起来：这条链才是"怎么用"

```
[入口] 参考图（手办图 / 彩色体块图，按目标网站换胃口）
   ↓  九特征点注意力修复，去破碎感、保人设
[生成] Tripo P2 / Meshy / 混元（P2 才有四边面 → 才能摘循环边）
   ↓
[拆件] 拓扑之后、UV 之前按部位拆（主骨骼/附加骨骼/无骨骼）
   ↓  或：自动 UV → 按 UV 岛选岛拆（仅未绑定资产）
[UV]   混元自动展 UV
   ↓
[贴图] 多级多角度正向投射：模型正交截图 + 旁边补高分辨率细节
   ↓  像素对齐 → nano banana 2 上色；仍有幻觉 → 参考图投射到 UV 岛 + 遮罩回轰
   ↓  不拆件方案：纹理图层 + UV 遮罩叠加
[绑定] 统一骨骼（小白人/自建 metarig）→ 权重数值编辑 → 验证
   ↓
[动画] 基础轨（带根运动）+ 叠加轨（相对旋转增量）
   ↓  骨骼 JSON 回传代替截图、虚拟骨标记尖端查穿模
[引擎] UE 里最终观感 + 材质/通道编辑（所见即所得）
```

## 7. 未证实 / 别当结论

- 「多级多角度正向投射技术」是**他自造的名词**，不是业界术语，检索时搜不到。
- 「Meshy 是硬参考、混元是软参考」是他的经验判断，**不是官方文档**；换版本可能变。
- 「收你 30 块 / 50 块」是他的报价，随行就市。
- 「拆分在 UV 之前」是他的 UE 模块化流程；**已绑资产不能回头改拓扑**，这条只对**新资产**成立。
- 「UE 蒙皮权重工具适合程序化」是**他个人的手感**（"我不是一个美术"），不代表它比 Blender 骨热更准。

## 第一篇 · 纹理坐标：把贴图当数学对象

> 这篇不是"贴图怎么画"，是"**用数学直接生成图案**，不依赖参考图"。意义：一旦把
> "纹理坐标 = 0..1 的二维坐标系"变成可计算的，**很多贴图就能用代码生成，而不是靠图像模型抽卡**。

### 1.1 一句话原理

- 「**纹理坐标，顾名思义，它是纹理的采样坐标**。它包含**红通道和绿通道**，分别代表每一个纹理像素的 **X 坐标和 Y 坐标**。」
- 「纹理也就是各种图片，它有**不同的尺寸**；为了让不同尺寸的图片都可以正常显示到屏幕上，纹理坐标是 **0 到 1 的坐标系**。」
- 「**纹理坐标往往有两个作用：一个是利用它的几何意义，一个是利用它的图形意义。**」
  - 几何意义：把 R 通道当 X、G 通道当 Y 去做**数学计算**；
  - 图形意义：拿这张渐变图去和图片**相乘/相减**，得到渐变效果。

**两个通道单独看**：
- R 通道 = 从左到右的渐变（黑=0，红=1）；
- G 通道 = 从上到下的渐变（最上=1，最下=0 —— **G 是反的**，画坐标系时要翻转）。

### 1.2 采样器的三种"看法"（点 / 线 / 面）

| 采样方式 | 怎么做 | 看到什么 |
|---|---|---|
| **点采样** | 给 UV 输入一个**常数**（如 `(0.5, 0.5)`） | 整张图变成一个颜色 = 图像中心那一个像素的颜色 |
| **线采样** | 把 UV 的 **X 通道接到 UV 输入**（U=V，采样落在对角线上） | 一条从左上到右下的斜线图 |
| **面采样**（正常） | UV 原样接进去 | 完整图案 |

### 1.3 缩放与平铺

「当我将纹理坐标**直接乘以二**的时候，再把它连到纹理的 UV 上，可以看到它就变成了**四个小的纹理**。」

### 1.4 扩展方式：Repeat vs Extend

- 「可以切换它的**扩展方式：Repeat（包裹）→ Extend（延伸）**。」
- **包裹（Repeat）**：纹理坐标**超出 0 和 1 的部分会被取小数**，然后无限重复 → 纹理重复效果。
- **延伸（Extend）**：超出部分被**强制截断到 0 和 1**，溢出的坐标颜色都被**固定到边缘像素**。
- 「因此我们的**贴图一般都要预留一下边缘位置**。如果你想要对它进行**缩放或者移动运算**，就需要**处理一下你的纹理参考图**了。」

> **结论**：程序化贴图里凡做 UV 加减乘除，**要么用 Repeat + 无缝图，要么用 Extend + 留边**。选错 = 边缘拉丝。

### 1.5 平移 = 采样位置偏移

- 「把纹理坐标的 **X 通道分离出来**，加一个 **time 节点**，就得到一个**不断往左平移**的效果。」
- 「**实际上每一个像素点的位置都没有变化，只是它们的采样颜色发生了变化**，从而导致了图片往左移动的错觉。」

### 1.6 把 UV 当坐标系，画点 / 线 / 函数（核心价值）

- **建坐标系**：「G 通道是反的，翻转过来让它从下到上；整个纹理坐标**减去 0.5**、**再乘以二**，就得到一个 **-1 到 1 的平面直角坐标系**。」
- **画点**：「计算**每个像素到某个坐标的距离，小于阈值就汇集成白色**，显示出一个点。」
- **画线**：「**Y = 0**：X 坐标 + G 通道连常量 0。举一反三：**Y = KX + B** —— X 乘 K 再加 B。」
- **画函数**：「二次函数：**X 乘 X 作为 Y**；三角函数：**X 乘 sin 作为 Y**。」
- **画面**：「**函数的 Y 减坐标系的 Y**，得到函数下方的所有点。」
- **让它动**：「把 **time 连到 X 项**，图像就动起来了。」

> **可执行的结论**：纹理坐标节点链 = **一个可编程的 2D 画布**。能做描边/条纹（距离阈值）、河流动画（R 通道累加 + 时间）、花纹（sin/cos 组合）、渐变遮罩（通道相乘）。**这些都不需要图像模型，也不需要参考图**——写节点公式即可。

## 第二篇 · AI 资产性能优化

### 2.0 开场结论

- 「AI 生成的模型**面数一般都很高**，就算使用 **AI 拓扑**也会有非常高的面。而**游戏道具模型，需要降低到 1500 个三角面以下**。」
- 「为了这个目标，我们需要一种**比 AI 拓扑面数更小、更可控的流程**。」

### 2.1 面数：几何抽象 → 硬边化 → 法线方向减面（5000 → 1300）

- 「首先对模型**几何结构的抽象**：相对于平滑模型，将其**抽象成棱角分明的多边形风格，保留生成模型的硬边效果**。生成的模型**保留低模的几何特征**，**整个模型由多个平面构成**。」
- 「配合（Blender）的**减面工具**或**虚幻引擎的减面工具**，**依据模型表面的法线方向进行减面**。」
- **实测数字**：「混元 AI 拓扑面数开到最小的时候，也保留了 **5000 面**；但用这套流程进行法线方向自动减面时，**可以削减到 1300 面**。」
- 「常规人工工作流中，我们需要有**完整的高模以及对应的低模**，才可以把细节**烘焙成法线贴图**；但是现在有了 AI，可以**直接根据抽象后的低模、根据原画参考直接画到低模上**——**跳过制作高模和传统手工烘焙**。」

### 2.2 顶点数：决定顶点的不只是面数

- 「仔细看图中这两个模型，它们**外观和面数完全一模一样**，但**顶点数量却是不一样的**。」
- 「模型的几何结构的顶点**仅仅是基础**。决定顶点数量的，还包括了 **UV 分割**和**软硬边设计**。」
- 「UV 上面会显示模型的每一个三角面需要映射的区域，每一块区域被称作一个 **UV 岛**。**岛的不同排布方式、分割数量**决定了**顶点的复用率**。」
- 「上图我画了三种不同的 UV 岛，都是由**八个三角面**构成，但顶点数量分别是 **8、9、10**。把一个 UV 岛**分成多个 UV 岛**，就会额外又**分裂出一对顶点**。」

#### 反直觉实测：合并 UV 岛反而**增加**顶点

- 「AI 生成的模型的 UV 往往是被**切碎**的，由**大量的 UV 岛**构成。难道 AI 生成的模型在顶点上面会比人工更高？我尝试着对 **UV 岛进行了一些合并**。**本以为合并之后会降低顶点的数量，但事实上——虽然看起来更为整体，消耗的顶点却远超原来的散状分布。**」
- 「猜测是因为**软硬边的影响：引擎会根据硬边自动拆分顶点**。例如一个锋利的刀刃，顶点就会理解为**左右两个顶点，存储左右两面不同的法线方向**。但**自动 UV 可以更大程度地应用本就应该拆分的硬边**，从而呈现**更小的顶点占用**。」

#### 顶点/面比 0.6（人）vs 0.77（AI）

- 「这个模型它的**面数和顶点比例只有 0.6**……**100% 是人手工制作的**。而 AI 生成的这个模型，**顶点占用率达到了 0.77**。」
- 「多出来的顶点：人习惯的建模方式是**穿插结构**，而 AI 生成的模型是**一体的**。人的穿插结构相对于完全一体的模型，**会多出来将近一倍的衔接顶点**。」
- 「（原）作模型只需要考虑结构、面数、贴图；AI 要考虑的东西就多了——**一体生成就完了，训练数据会给出答案，所以天然就是一体的**。」

> **一体壳在顶点占用上是优势**（省衔接顶点），利于渲染性能。

### 2.3 UV：碎 UV 伤缓存命中，但利用率高

- 「引入一个叫做**纹理缓存命中**的概念……有没有一种办法把上一帧中出现的**纹理像素存储起来**方便快速读取？**恭喜你发明了 GPU 缓存**。」
- 「工作原理就是把可能会出现的纹理像素放到一个**体积特别小、但读取速度特别快**的缓存空间中……**总共 128K 字节**……当摄像机**静止或者缓慢转动**的时候，大概率就可以从缓存中读取。」
- 「**缓存命中和缓存未命中的性能差距，可能达到 100 倍**。这也是为什么我们**快速转动摄像头**时，游戏中往往会出现**卡顿**——因为会出现大量的缓存未命中。」
- 「为什么说 UV 不能太碎？**当我的 UV 是一个整体的时候，模型上的分布往往也是相连的**，GPU 长期把周围的纹素缓存起来的时候，就有大概率被命中。但**如果 UV 岛特别小，就无法享受到这种缓存优化**，因为周围一圈都是**其他的 UV**，分布在模型上的位置**和空间无关**，会导致纹理缓存**非常不稳定**。」
- **取舍**：「UV 虽然破碎，但**它的利用率比手动排布的要高**，可以采用**更小的纹理尺寸**达到更好的细节效果。」「这和你的**游戏类型和当前短板**有很大的关系。**只有优化短板才可以带来真正游戏体验的提升**，而不是一味的性能焦虑……**有的时候自动 UV 也是不错的选择**。」

### 2.4 贴图：4K 10,000KB → 43KB

- 「AI 生成一般是**超分辨率，4K 甚至 8K 的图**去生成，但实际**不需要这么多像素**也可以实现很好的效果。」
- 「一个很大的纹理，不仅仅是**占用空间变大**……一张 **4K 图达到了足足 10,000KB**（≈10MB）。可以在**虚幻引擎中右键对它缩小尺寸**。」
- 「纹理**一定要是 2 的倍数**，因为需要生成 **mipmap**（根据距离显示不同精度的贴图），这个是引擎自动做的。如果不是 2 的倍数，**无论多远都是这个最高精度**。」
- 「不断降低纹理尺寸，降到**视觉上差别小、看起来效果不会有太明显变化**的状态。实际占用：**从 10,000KB 降低到了 43KB**。**一张图可能就可以多塞无数张图**。」

## 未证实 / 别当结论

- 「缓存命中差 100 倍」「128K 字节」是他口述的近似数，**不是实测基准**；用之前按自己的 GPU/引擎量。
- 「顶点/面 0.6 vs 0.77」是**两个具体模型的个例**，不是人群统计。
- 「混元 AI 拓扑最小 5000 面」是当时的版本，随时会变。
- 纹理坐标那篇是 Blender 材质节点课，**与 OpenAGI 仓库无关**，是通用技术底座。

> **一句话**：把「生成 3D 模型」从**手工流水线**改造成**可编程节点图**——每个 AI 调用是一个有输入输出的函数节点，
> 节点之间的逻辑自己写；用一张节点图跑完「图像分类 → 提示词精修 → Tripo 生成 → 四视图审查 → 抽卡门禁」，

## 1. 工作站的分层结构

```
┌──────────────────── 工作站（Electron/本地，数据不出机） ────────────────────┐
│  模型商店   把语言模型/生图模型当"应用"下载安装；一次配置，多端运行            │
│  应用层     每个 app 一个功能块（对话 / 生图 / 建模 / 爬虫 / 视图工坊 …）      │
│  连接层     API 接 DeepSeek 之类；也可纯本地（Ollama + ComfyUI 桥）            │
│  工作流平台 ← 与"别人的一键工作流"最大区别：AI 工作逻辑**可编程**             │
│     节点图：数据节点（文本/图像/模型）→ AI 节点 → 工具节点（Tripo 桥/网页脚本）│
│  沙箱/虚拟平台：保证数据安全，不必联网                                       │
└──────────────────────────────────────────────────────────────────────────┘
```

- 「经过一段时间的迭代，我的工作流已经升级成了一个**工作站**，还有一个相对完整的**模型配置和资产管理系统**。」
- 「它支持**配置本地模型**，连接后端的 **Ollama**，然后有一个**模型应用商店**——你只需要在商店里面下载自己想要的模型。」
- 「开发理念是**一次配置多端运行**：配置自己的语言模型和生图模型，就可以使用里面的**所有应用**。」

- 「左边的是**工作流平台**，也是相对其他平台最大的区别之处：**它的 AI 工作逻辑是可编程的**。」

## 2. 可编程工作流：节点 = AI 函数

### 2.1 节点化

- 「可以输入的各种数据，目前只支持几种基础数据类型：**文本、图像、模型**，后面可能会支持表格。」
- 「AI 的各种工作事务被**节点化**——每个节点有它的**输入和输出**。AI 的工作就是把所有的输入按照你给的提示词进行处理，然后**输出到下一个节点**。」
- 「**节点和节点之间的工作逻辑全部可以由你自己制定**。」
- 「如果你用过 **ComfyUI 或者虚幻引擎的蓝图**这种可视化编程系统，应该对这个很熟悉——其实就是**把 AI 当作一个一个函数节点**，让它融入到编程逻辑之中，实现**智能判断、智能分支、图像识别和智能脚本**。」

### 2.2 示例工作流（可直接照抄的模板）

```
[输入：用户上传的图像]
   │
   ├─ 节点1 图像分类：判「人物 / 道具 / 怪物」            ← AI 判断
   │
   ├─ 分支 A（人物）                                        ← 编辑节点逻辑（自己写）
   │    └─ 节点2 提示词组装：模板 + 撰写要求
   │         └─ 节点3 智能分析：结合图像识别 + 提示词要求，精修提示词
   │              └─ 节点4 Tripo 桥（工具节点）：调 Tripo 生成
   │                   ├─ 节点5 图像压缩（"AI 识图不需要特别精确，压缩图像可以提高处理速度"）
   │                   └─ 节点6 自动抽卡 + 严格门禁：对结果打分/审核 → 选或重抽
   │
   └─ 分支 B/C（道具 / 怪物）：另一套提示词与处理逻辑
```

- 「它会根据用户上传的图像进行**分类**，把任务**路由到不同的处理逻辑**上，每种逻辑由我精心调校的提示词……判定他是人物、道具还是怪物。」
- 「这里发现他是人物，就会走入到这个分支，这里有我提供的**提示词模板和提示词撰写要求**，然后进入到这个**智能分析任务**——AI 会结合图像识别以及提示词要求，对提示词进行**精细化修改**。」
- 「然后这里会使用到一个 **Tripo 桥**，也就是各种**可执行的工具或脚本**，这里就是使用了 Tripo 的生图功能。」
- 「再往后走就是**图像压缩**，因为 AI 识图并不需要特别精确，压缩图像可以提高它的处理速度。」
- 「然后这个就是**自动抽卡能力**：AI 生成之后可以通过制定任务让他负责，**对生成的结果进行一次严格门禁**。」

> **核心认知**：**"分类 → 分支 → 分支内专用提示词"的结构比任何提示词技巧都值钱**——一份万能提示词一定劣于"先分类再各给专用提示词"。

## 3. 建模全过程（25 分钟实录）

### 3.1 总流程

```
① 原画输入
② 九特征点提取 → 注意力机制修复原画（保人设 + 3D 化）
③ 得到「无幻觉标准模型参考图」（正面单视图，几何结构 + 正确深度）
④ 丢给 Tripo P2 生成（必须 P2，否则没有四边面/循环边）
⑤ 四视图审查（精度高到肉眼难分好坏 → 打算让 AI 做像素分析、四选一或重抽）
⑥ 导出 → 三拆：按脖子把「头 / 身」分开（Maya 涂抹工具刷出脸）
⑦ 分部位贴图：每部件渲真实四视图当"严格参考"，做像素对齐
⑧ 回建模软件组装 → 不满意再抽卡
```

### 3.2 ②③ 幻觉修复与「无幻觉参考图」

- 「他会有自己的**注意力机制**，对原画进行修复，比如**提取原画中的九个特征点**，来保留人设的同时对原画进行 3D 化。」
- 「这个是经过**幻觉修复后的原画**：通过注意力机制关注**鞋子、衣服、头发、头饰**等各种细节，然后再把他们尝试**融合到一个人物**上。看起来跟原来差不多，但**大幅度削减了一些破碎感**，然后就可以生成**完全无幻觉的标准模型参考**。」
- 「然后这个无幻觉的 3D 模型参考，丢到 Tripo 的 **P2 模式**会有奇效。但并不是所有的生模型网站都适合这种，**因为这跟模型的训练集有关**：有些模型会把**网格线识别为凹痕**，有些会把它识别成**立体结构**。」
- 「不过这种参考图对精度要求极其严苛。我现在的流程是通过**正面单视图**去做，所以你的**正面不仅要有几何结构，还要有正确深度**；你的**原画也要完全吻合模型的几何结构，实现像素对齐**才行。」

### 3.3 ④ P2 与「必须四边面」

- 「首先找到脖子的这部分**四边面是必要的**，所以我一直强调**必须得是 P2**，要不然你这**循环边就摘不出来**。」
- 「然后在这里**插循环边**，删除这个循环面，这样就可以把它**分离成两部分**。」

> **没有四边面，连"沿脖子插一圈环线把头和身分开"都做不到**，只能靠框选/岛选。

### 3.4 ⑥ 三拆：为什么必须拆

- 「选择好模型之后就可以导出拆分。现在的工作流主要是**一体生成、分件上色**。」
- 「在这里我不得不再次点名一下 Tripo：**哪怕我把参考图都跟模型完全吻合上了，依旧生成了贴图有幻觉**，所以导致我不得不将它**拆成多部位进行贴图**。」
- 「在这里我使用 **Maya 这个涂抹工具把脸给涂出来**，然后再沿着脖子给它分成脑袋和身体两部分来生成。」
- 「等后面**自动化**做好了就可以做**四拆五拆**，到时候精度应该还可以再提高一倍，而且**零人工成本**就可以直接躺平喝茶啦。」

> **贴图幻觉的根因不是参考图不够准，是"一张图要覆盖整个模型"**。参考图对齐能压制，但压不死；**拆件 + 逐件生贴图**才是根治手段。

### 3.5 ⑦ 分部位贴图的「四视图严格参考」

- 「根据每一个拆分部位，用**模型渲染出真实的四视图**。当然这部分我已经在研究自动化了——到时候做个节点：输入模型、输出四视图。」
- 「**四视图的深度和轮廓**，可以作为生成贴图参考的**严格参考**，能够最大限度**限制像素偏移**，从而实现一种叫做**像素对齐**的完美贴图。……就相当于**直接告诉 AI 正确答案，让他抄答案**，而不是说凭自己的想象自由发挥。」
- 「这部分工具已经做出来了，但是**还没有集成到我的工作站上**。等我完全集成、实现全自动化和**自动像素匹配检验节点**的时候，这些全部都可以完全脱离人工干预。」

### 3.6 收尾的现实（他也没解决的两件事）

- 「现在目前这种**三拆的工作流，可以把时间压缩到 25 分钟**。」
- 「现在的**最大问题其实还是贴图**：不管我给的参考图多么精确，他总是给我**模糊一点**，这让我一个完美主义者非常的不适。」
- 「我后面还是打算让 **AI 做像素分析**，把原画和提取出来的九个特征点，跟生成的模型四视图进行对比，找出**缺失结构**，然后**四选一**选出最好的那个，或者**再次进行抽卡**。」

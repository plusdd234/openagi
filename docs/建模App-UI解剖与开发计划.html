01UI 解剖：这套界面由什么组成

Maya 的界面本质是「中间一个大视口 + 四面包围的功能带」。它不是九个独立面板，而是三个层级：全局命令层（菜单 / 状态行 / 工具架）、场景层（大纲 / 视口 / ViewCube）、属性层（建模工具箱 / 属性编辑器 / 通道盒）。我们照这个骨架搬，不照它的功能量搬。

三个层级（比区域名单更重要）

命令层 菜单栏、状态行、Shelf、视口标题行 —— 负责「发出命令」，不持有数据。
场景层 竖工具条、大纲、视口、ViewCube —— 负责「看与选」，只读场景与网格。
属性层 建模工具箱、属性编辑器、通道盒、命令行 —— 负责「改数值 / 改模式」，写命令不改内存。
搬骨架的判断标准：同一个动作只能有一个入口逻辑。菜单、Shelf、快捷键、命令行都调到同一个 Command，界面只负责参数收集与回显。

04开发架构：九个模块、一条依赖线

结论来自 Astra 评审 + 本项目「零构建、纯 script、全局命名空间」的硬约束。核心修正：在八层中补一个 evaluator/cache，视口只读求值结果，不直接理解拓扑操作。

⑨ ui-shell菜单栏 / Shelf / 大纲 / 属性编辑器 / 通道盒 / 命令行 / 快捷键 / HUD。只发命令、只回显，不改网格内存。
▼ 只能调用下一层
⑧ viewportthree.js 渲染、真实边线与顶点、高亮、软选择热力、ViewCube、四视图、拾取代理。只依赖「只读求值网格 + 选择集」。
▼
⑦ tool-controller模态工具状态机（移动/旋转/缩放/挤出/环切…）、轴约束、吸附、数值 HUD；拖动中预览，松手提交。
▼
⑥ command-historyCommand 栈：before/after/选择变化/合并规则；一次拖动一条记录；64MB 预算。
▼
⑤ selection对象/顶点/边/面模式、ID 集合、点线面转换、框选套索、操作后的选择迁移。
▼
④ topology-ops纯函数算子：mesh + params → {mesh, patch, remap}。不碰撤销、不碰 UI、不碰 three.js。
▼

05持久化与需要你拍板的决策

可编辑网格比参数化 spec 大一个量级。现有硬约束是「单个 GLB + 只替换 JSON chunk + 不动 BIN」，Astra 的长期建议是把网格写进 BIN。两者冲突，MVP 先用折中方案，把选择权交给你。

D1 · 网格存哪里？

A：JSON + base64 类型数组（推荐 MVP-1）。顶点坐标、面偏移、面索引、稳定 ID 编码成 base64 放进 extras.seedModel.mesh，仍然只替换 JSON chunk，完全符合现有约束；1 万面约 1–2 MB。B：写进 BIN chunk + accessor（更省体积，但要改导出器和「不动 BIN」约束）。

建议：MVP-1 选 A，面数硬上限 1 万；MVP-2 再做 B 并把 schema 升到 3。

D2 · modeler.js 参数化内核怎么处理？

不删。降级为「基础体 / 曲线工厂」：新建对象时调用它生成几何，随后立刻烘焙成 face-vertex 网格。mode:'parametric' 不再是文档主模式；旧的 v1 资产打开时自动烘焙为可编辑网格，保存后写 v2。

建议：保留文件，转换逻辑单独一层（scene-doc 的 fromV1）。

D3 · 底部时间轴要不要？

Maya 的底部是动画时间轴，本产品不做动画。该区域改为命令行 + 反馈行，既保留通用建模软件的操作习惯，又不做一堆假控件。

建议：不做动画，不保留时间轴占位。

D4 · 修改器栈放哪一层？

数据放 scene-doc 节点（modifiers: []），求值放 evaluator。MVP-1 只保留接口与空数组，不做 UI；否则会同时承担拓扑、参数依赖、缓存、撤销四套复杂度。

建议：接口先留，功能进 P3。

D5 · 材质与贴图怎么接？

继续遵守既有约束：文档只存 slotNames + textureConfigKey，贴图真源仍在 m3d-slots.js 的 openagi_model_tex_v1。建模 App 只负责新建/重命名材质槽，不复制贴图配置。

建议：MVP-1 只做槽位，不做材质编辑器。

09与 Astra 的评审记录

上一轮已通过用户账号下的 gpt-6-astra（OpenAI 兼容接口）完成一次架构评审，回答原文如下，落地时采纳了三项：face-vertex 不选 half-edge、补 evaluator/cache 层、Command 负责事务而 patch 只管数据。
本轮（2026-11-03，UI 外壳落地后）想带新界面再复核一次，但接口返回 HTTP 403「账户余额不足」，未能发起对话；下面保留上一轮原文，并列出待补问的清单。

Astra 回复原文（约 2400 字，点击展开） 
总体分层合理，但应补一层 `evaluator/cache`：负责 modifier 求值、显示网格缓存和脏标记。`viewport` 不应直接理解拓扑操作。

1. **mesh-core：选折中方案，不选完整 half-edge**

   用 `face-vertex`：顶点数组、面顶点索引、面 offset；另维护按需生成的 `edgeTable`，操作完成后重建边表和邻接缓存。几万面、纯 JS 下足够，内存和调试成本明显低于 half-edge。

   half-edge 适合高频局部拓扑操作和复杂洞/边界处理，但每次拆分、合并都要维护大量互链，纯 JS 中 bug 成本高。后续性能确实不足，再把局部算子升级为 half-edge，不要一开始全量引入。

2. **拓扑算子与撤销**

   算子保持纯函数：`mesh + operationParams -> {mesh, patch, remap}`。预览时在原网格上计算临时结果，鼠标拖动结束才提交。

   外层必须有 `Command` 对象，负责旧状态、新状态、选择变化、材质变化和合并规则。patch 只解决数据差异，不负责事务、撤销栈和交互生命周期。MVP 可先保存局部快照，复杂 patch 后置。

3. **选择集与稳定 ID**

   顶点、边、面都使用文档级稳定整数 ID，不直接暴露数组索引。mesh 内部使用 `id -> dense index` 映射；删除后索引可压缩，ID 不复用。

   拓扑操作返回 `created/deleted/remap`，选择系统据此迁移选择。边 ID 应由端点 ID 的规范化组合生成；发生拆边时创建新 ID。选择历史只保存 ID 集合，不保存索引。

4. **three.js 显示与拾取**

   实体面使用 indexed `BufferGeometry`；真实边线由拓扑边表生成独立 line buffer；顶点使用 points 或 instanced marker。软选择权重写入顶点颜色，实体材质开启 vertexColors。

   不做多 pass。每次提交或预览时统一生成显示缓存，静态拓扑不重复构建。MVP 用 raycast：对象模式射线命中 mesh，组件模式用三角形、边线和点的独立代理拾取。几万面仍可接受。GPU picking 等稳定性和维护成本不值得放入 MVP。

5. **零构建文件边界**

   建议文件顺序：

   `seed-core.js`、`scene-doc.js`、`mesh-core.js`、`mesh-selection.js`、`topology-ops.js`、`command-history.js`、`tool-controller.js`、`mesh-viewport.js`、`model-ui.js`。

   依赖只能向下：`ui -> tools -> command/selection/topology -> mesh/scene`，`viewport`只依赖只读数据接口。可以引入极小注册器，但只注册服务和工厂，不用它隐藏依赖；优先通过 `window.SeedModel.*` 命名空间暴露模块。

6. **修改器栈**

   放在 `scene-doc` 的节点数据中，求值放入新增的 `evaluator/cache`。每个 modifier 接收 evaluated mesh，返回新 mesh；基础编辑始终作用于 base mesh。

   MVP 不实现修改器，只保留 `modifiers: []`、`evaluate()` 和缓存失效接口。否则会同时承担拓扑、参数依赖、缓存和撤销四套复杂度。

7. **GLB 持久化**

   长期推荐：网格顶点、面 offset、面索引、稳定 ID、材质槽写入 GLB 的 BIN，通过 JSON chunk 中的 bufferView/accessor 描述；`extras.seedModel` 只存 schema、节点、编辑元数据、选择和 slotNames。不要把完整拓扑塞进 JSON。

   但现有"只替换 JSON、不动 BIN"约束下，MVP 只能使用紧凑 JSON 数组或 base64 数据，并限制文档规模。应增加 `schemaVersion: 2` 和 `storage: json|bin`，读取同时兼容 v1；完成 BIN 写入后迁移，旧文件继续可读。

8. **MVP-1，按依赖排序**

   1. scene-doc 多对象节点树、变换、材质槽、稳定 ID。
   2. face-vertex mesh-core、边表、BufferGeometry 缓存。
   3. 对象/顶点/边/面选择、框选、选择迁移。
   4. 移动/旋转/缩放、轴约束、数值输入、一次拖动一次撤销。
   5. 立方体/平面/圆柱基础体。
   6. 挤出、内插、合并、删除面；真实边线和组件拾取。
   7. Outliner、Attribute/Channel 面板、四视图、ViewCube、网格吸附。
   8. GLB v1 读取、v2 JSON 写入、desk 集成、撤销重做验收。

   明确不做：half-edge、修改器、UV 展开、软选择、桥接、环切、倒角、镜像、阵列、GPU picking、复杂材质、动画和多人协作。

   验收指标：1 万面场景交互保持可操作；上述算子可撤销/重做；四视图选择结果一致；关闭重开后拓扑、变换、材质槽和选择可恢复；旧 v1 文件可打开。

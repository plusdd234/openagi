## 1. 调研：专业剪辑软件怎么「操作」

参照对象：Premiere Pro（PR）、DaVinci Resolve（DR）、Final Cut Pro（FCP）、Avid Media Composer（AV）、剪映专业版（CP）。

### 1.1 时间线手势的分层

| 手势 | 语义 | 参照 | 用户预期 |
| --- | --- | --- | --- |
| 拖片段本体 | 改 `start`，可跨同类轨道 | 全部 | 空白处落下＝留空隙 |
| 拖边缘 | 改 `in` 或 `dur`，不动邻居 | 全部 | 有素材余量才能拉长 |
| 拖边缘 + 修饰键 | 波纹 / 滚动 | PR、AV | 波纹＝后续整体前移；滚动＝只动接缝 |
| 拖片段 + 修饰键 | 滑移 / 滑动 | PR、AV | 滑移只改内容入点；滑动改位置并挤邻居 |
| 空白处拖拽 | 框选 | 全部 | 点一下＝定位播放头，拖开＝框选 |
| 拖到窗口边缘 | 自动滚动 | 全部 | 长片素材必须能拖到屏幕外 |

**结论**：手势不在多，而在「同一动作的默认语义稳定」。剪辑台已实现前四行，缺框选与拖拽自动滚动。

### 1.2 编辑的锚点：播放头、入出点、轨道目标

- **三点编辑**（PR/AV/FCP）：源素材入点 + 出点 + 时间线插入点 = 一次编辑。核心不是「源监视器」这个 UI，而是 `插入（insert）` 与 `覆盖（overwrite）` 两种落点语义。
- **插入**：在播放头处撑开空隙，后续片段整体后移；**覆盖**：直接盖掉范围内的旧内容，必要时把头尾片段切开。
- **入出点（I / O）**：既用于「只播这一段」，也用于「只导出这一段」。专业软件里入出点是**序列级**状态，不挂在片段上。
- **轨道目标（track targeting）**：粘贴、插入、覆盖都要知道「落到哪条轨」。没有轨道目标时，必须有稳定的推断规则（同类首选轨）。

**结论**：剪辑台缺入出点、插入/覆盖、剪贴板与轨道目标推断。

### 1.3 播放与预览

- **JKL**：L 连续按加速（1×→2×→4×），K 停，J 倒放；倒放不需要解码器支持负速率，逐帧回退即可。
- **逐帧**：`,` / `.`；**跳到上/下一个剪辑点**：`↑` / `↓`（PR）或 `Shift+←/→`。
- **循环**：整片循环与「入出点区间循环」是两种；剪辑台应支持后者。
- **性能**：预览用 DOM 媒体元素最省事，导出用 Canvas 最可控；两者必须共用同一份参数采样，否则一定漂移。

### 1.4 效果与调色

- 专业软件的效果是**可叠加、可排序、可逐项开关**的栈；单一 `filter` 字段是玩具级模型。
- 效果参数必须能被「预览 / 导出 / 截图 / 缩略图」四条路径同时读到；任何一条路径自己拼 CSS 都会产生不一致。

### 1.5 字幕与音频

- 字幕在专业软件里是**独立轨 + 批量样式 + SRT/VTT 交换**，不是散落的文字片段。
- 音频轨必须有**波形**（判断对白/气口）与**电平表**（判断削波）；没有波形的音频轨在专业用户眼里等于不可编辑。

### 1.6 撤销与历史

- 专业软件的撤销是**语义化**的（「波纹删除 3 个片段」），并且有历史面板可以直接跳回某一步。
- 只存 JSON 快照不存标签，用户无法判断「撤销三次」会回到哪里。

## 2. 编辑修改的优化策略

1. **意图优先**：默认手势对应最高频意图，低频变体放修饰键；不新增需要记忆的独立工具。
2. **播放头即锚点**：分割、粘贴、插入、覆盖、打点都以播放头为参照，避免「先选中再猜位置」。
3. **非破坏 + 单步撤销**：一次用户动作＝一条历史；拖拽中实时改数据，松手才落历史。
4. **覆盖而非叠加**：同一轨道同一时间只允许一个片段生效；粘贴/覆盖必须先清理目标区间。
5. **吸附可预期**：吸附对象固定为「片段边缘 / 播放头 / 标记 / 入出点」，并能整体关闭。
6. **单一渲染路径**：参数采样、效果链、文字排版只保留一份实现，预览与导出共用。
7. **降级可见**：能力缺失（波形解码失败、WebCodecs 不可用）必须静默降级且不阻塞编辑，不伪造结果。
8. **可测试性**：所有编辑语义都提供纯函数或 `__test` 入口，断言数值而不是截图。

## 4. 本批改良计划与验收

### 4.1 数据层：schema v3 + 效果栈

- 片段新增 `effects: [{ id, type, enabled, preset?, params? }]`，类型限定 `preset / adjust / blur`。
- 删除 `clip.filter` 单一字段，迁移时把旧 `filter` 转成一条 `preset` 效果；迁移幂等。
- `effectsCss(clip)` 是唯一的效果拼装函数，预览（DOM `style.filter`）与导出（`ctx.filter`）共用。
- 验收：v2 项目迁移后 `effects` 命中旧滤镜；v3 再迁移结果不变；`effectsCss` 随开关/排序变化。

### 4.2 渲染层：统一 `renderFrame`

- `renderFrame(ctx, W, H, t)` 负责背景、视频层、文字层；导出与「导出当前帧 PNG」共用。
- 参数采样统一传 `t`，不再读全局 `S.time`，保证任意帧可重放。
- 验收：同一 `t` 连续两次抓帧像素一致；关闭某条效果后同一像素改变。

### 4.3 操作层：入出点 / JKL / 插入覆盖 / 剪贴板 / 全轨切分 / 框选

- 入出点：`I` 设入点、`O` 设出点、`Alt+I` / `Alt+O` 清除单边、`X` 清除区间；标尺显示区间；循环播放优先在区间内循环；导出可选「仅选区」。
- JKL：`L` 播放并 1×/2×/4× 加速，`K` 停止并复位，`J` 倒放（逐帧回退，不依赖负速率解码）。
- 插入/覆盖：素材右键菜单提供「追加 / 插入到播放头 / 覆盖到播放头」；覆盖前用 `clearRange` 清理目标区间（必要时把头尾片段切开）。
- 剪贴板：`Ctrl+C` 复制选中（保留相对间距与关键帧），`Ctrl+V` 以播放头为锚点粘贴，落到同类可用轨道并覆盖目标区间。
- 全轨切分：`Ctrl+K` 在所有未锁定轨道上切开播放头处的片段，一次历史。
- 框选：空白处点按＝定位播放头，拖开＝框选相交片段；多选时保持相对间距；拖到时间线左右边缘自动滚动。
- 验收：区间循环在出点回到入点；插入后后续片段整体后移；覆盖后中间片段被切成两段；粘贴后片段数、起点、关键帧正确；框选命中数与几何一致。

### 4.4 字幕：SRT / VTT

- `parseSubtitles(text)` 支持 SRT 与 WebVTT（含 cue id、`HH:MM:SS.mmm`）。
- `buildSrt(clips)` 从文字片段生成 SRT，时间码毫秒、序号连续。
- 文字面板提供「导入字幕」「导出字幕」；导入落到字幕文字轨，样式取「字幕条」预设。
- 验收：往返解析时间误差 < 1ms；导入 N 条＝新增 N 个文字片段；导出文本可被自身解析器读回。

### 4.5 音频：波形与电平

- 解码音频（`AudioContext.decodeAudioData`）后压成每秒 100 点的峰值数组，只存峰值不存解码缓冲，内存有界。
- 音频片段内绘制波形；缩放/滚动按当前像素宽重绘。
- 主输出接 `AnalyserNode`，传输栏显示双声道电平；暂停时归零。
- 解码失败（自定义协议、损坏文件）静默跳过，波形区留空，不影响播放与导出。
- 验收：1 秒正弦波解码后峰值点数 > 10、峰值 > 0.05；无音频时 `peaks` 返回空而不抛错。

### 4.6 可用性：语义化历史

- 历史项改为 `{ label, snap }`；所有写入点必须给文案。
- 项目面板列出最近 8 条，点击可回到该动作之前的状态。
- 验收：执行「分割 / 覆盖 / 粘贴」后历史标签可读；点击历史项后片段数回到对应值。

## 5. 不在本批范围

- 同轨转场（需要同一轨道双解码器 + 重叠语义）。
- MP4 封装、WebCodecs 硬件编码（需要 vendor 封装器，另立提案）。
- 蒙版、抠像、混合模式、LUT、示波器。
- 源监视器与完整三点编辑（本批只做时间线侧插入/覆盖）。
- 代理媒体、预渲染、云协作。

这些方向已在 `docs/提案-剪辑台-专业能力开发方案.md` 中列明，未实现前不会在 UI 上出现入口，避免「有按钮没能力」。

## 7. 风险与对策

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| `ctx.filter` 与 DOM `filter` 对 blur 的边界处理不同 | 预览与导出轻微差异 | 只把 `blur` 当作主观效果，数值断言只比较「开/关差异」不比较逐像素相等 |
| 倒放逐帧 seek 在高码率素材上卡顿 | J 键体验差 | 倒放节流到每秒不超过 30 次 seek；只更新当前帧，不播放音频 |
| 覆盖切开片段导致关键帧错位 | 动画跳变 | `kfSlice` 按局部时间切片，边界点保留；探针断言切片后关键帧时间单调 |
| 波形解码占内存/CPU | 导入大文件卡顿 | 只存峰值（100 点/秒），解码后立即释放 AudioBuffer；并发解码串行 |
| 粘贴覆盖误删用户内容 | 数据丢失 | 粘贴是单步历史，可一次撤销；覆盖前不改动其他轨道 |

补充说明：

- **入出点是会话级状态**，不写入项目文件（`.hfstudio` / 本机存档只存 `project`），与 PR 的序列级入出点仍有差距；重新打开项目后需重新设点。这是刻意取舍：避免把「临时查看范围」误存成项目数据。
- 关键帧切片 `kfSlice(kf, from, to)` 与片段切割 `cutClip` 是同一套原语，覆盖 / 粘贴 / 插入产生的边界都走它，不存在第二套关键帧搬运逻辑。
- 波形解码失败（自定义协议、损坏文件）静默跳过，波形区留空，不影响播放与导出。
- 本批未改 `js/`、`css/`、`index.html`，仅改 `apps/studio/`、`tools/probe-studio.js`，并按规范重新生成 `apps/manifest.js`。
- 未跑 `--all` / `--full`：改动范围只在单 App 目录与 manifest，不属于共享层变更。

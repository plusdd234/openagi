# 提案：剪辑台专业能力开发方案

- 状态：**进行中**（Phase 0 / Phase 1 已落地并通过探针；Phase 2–5 仍为计划目标）
- 日期：2026-11-13
- 适用范围：`apps/studio/`（剪辑台）。不涉及 `js/`、`css/`、`index.html` 共享层，不修改 `AGENTS.md`。

> 本文区分「已实现」与「计划目标」。已实现部分以当前代码与探针为准；计划部分均给出可执行的验收路径，未验收前不视为完成。

---

## 1. 目标与边界

### 1.1 目标

把剪辑台从「能剪一条片子」提升到「接近专业 NLE 的日常可用度」，参照对象：

| 缩写 | 软件 |
| --- | --- |
| PR | Adobe Premiere Pro |
| DR | DaVinci Resolve |
| FCP | Final Cut Pro |
| AV | Avid Media Composer |
| CP | 剪映专业版 / CapCut |
| FR | Wondershare Filmora（当前产品形态的直接参照） |

### 1.2 运行环境约束（不可违背）

- 纯 Web：Electron / Edge 加载 `file://.../index.html`，不启动固定端口服务。
- App 只改 `apps/studio/`；窗口 DOM 内联在 `body.js`，样式全部 `.st-*` 前缀。
- 素材只经 `window.playerApp.files()` / `_urlOf()` 读视频库；不碰 `window.openagiDesktop`。
- 测试默认无头、`?nostore=1` 不写真实存储、产物只进 `.workbuddy/runs/`。
- 导出优先浏览器原生能力；不引入需要联网或独立守护进程的依赖。

### 1.3 本方案不做

- 云端协作、账号体系、多机位直播。
- 内嵌 AI 生成（后续若做，必须走 `LLMRouter`，不在本方案范围）。
- 修改桌面外壳、注册表协议、共享样式。

| 测试 | `tools/probe-studio.js` 56 项断言，统一入口全绿 | `tools/test-headless.js studio` |

**结论**：Phase 0（数据地基 / 关键帧 / 项目文件 / 快照）与 Phase 1（动态轨道 / 精细剪辑 / 多选 / 标记）已落地。剩余差距集中在统一合成器、转场与效果栈、字幕与 SRT、音频波形与电平、MP4 导出。

### 2.1 本轮已实现（Phase 0 / Phase 1）

- 项目 schema `v: 2`：`tracks[]`、`markers[]`、`sampleRate`、`meta`；`migrateProject` 支持 v1→v2 且幂等。
- 关键帧：`clip.kf[prop] = [{t, v, ease}]`，`sampleTrack` 端点钳制 + 段内缓动；预览、导出、检查器共用 `propAt` / `visualOf`。
- 项目文件：导出 v2 JSON（`.hfstudio`），导入保留视频库素材与文字，剔除跨会话失效的 objectURL。
- 自动快照：5 分钟或 50 步落一份，保留 5 份；主存档缺失时用最近快照兜底。
- 动态轨道：增删轨道、锁定 / 静音 / 独奏 / 隐藏、拖高；预览池与时间线随轨道重建。
- 精细剪辑：Alt+边缘＝波纹裁剪、Ctrl+边缘＝滚动剪辑、Alt+片段＝滑移、Ctrl+片段＝滑动；Shift/Ctrl+点击多选；`Shift+Delete` 波纹删除。
- 标记：`M` 打点、标尺渲染、磁吸、Alt+点击删除。
- 右键菜单：片段上右键可分割、分离音频轨道、静音、复制、删除、波纹删除；分离后原视频静音，音频片段落到音频轨并沿用入点 / 时长 / 音量关键帧。
- 界面框架：顶部菜单栏（文件 / 编辑 / 视图 / 帮助）复用现有能力；选择 / 剃刀两种工具（V / B），剃刀点击片段即在指针处切割；循环播放、逐帧步进（`,` / `.`）、适配时间线（F）、缩放百分比；帮助菜单内置快捷键面板。

### 2.2 未完成（后续 Phase）

- 统一合成器 `renderFrame(ctx, project, t)`：目前预览是 DOM、导出是 Canvas，两条路径靠 `visualOf` 保持数值一致。
- 转场、音频交叉淡化、可叠加效果栈、蒙版 / 抠像 / 混合模式。
- 字幕轨与 SRT / VTT、批量字幕样式。
- 音频波形、电平表、轨道增益 / 声像、EQ / 闪避。
- MP4（H.264 / HEVC）：当前只有 MediaRecorder WebM，无 MP4 封装器，**不伪造 MP4 输出**。
- WebCodecs 硬件编码、代理 / 预渲染、播放分辨率降级。

## 4. 差距收敛：优先级清单

### P0（专业可用性的硬门槛）

1. **项目 schema v2 + 迁移**：嵌套 `transform` / `audio` / `effects` / `keyframes`，`normalizeProject` 前加 `migrateProject`。
2. **统一合成器**：预览与导出共用 `renderFrame(ctx, project, t)`，替换「DOM 媒体层 + Canvas 导出」两套逻辑。
3. **关键帧**：任意数值属性可打点、线性/缓动插值、撤销可回退。
4. **精细时间线**：动态轨道 + 轨道头（锁定/静音/独奏/隐藏/高度）、波纹/滚动/滑移/滑动、多选与成组。
5. **转场与效果栈**：视频转场、音频交叉淡化、可叠加效果。
6. **字幕轨 + SRT/VTT**：导入生成文字片段，导出带时间码。
7. **音频基础**：波形、电平表、片段/轨道增益、淡入淡出。
8. **导出升级**：WebCodecs H.264/MP4 优先，MediaRecorder WebM 回退；导出预设与取消。
9. **项目文件与恢复**：`.hfstudio` 导入导出、自动保存、崩溃恢复。

### P1（显著提质）

调色（LUT/曲线/色轮/示波器）、蒙版与抠像、混合模式、速度重映射、音频 EQ/闪避、代理与预渲染、播放分辨率降级、标记、快捷键配置、撤销历史面板、右键菜单、素材箱与代理媒体、源监视器与三点编辑。

### P2（进阶）

嵌套序列、多机位、场景检测、音频自动同步、语音转写、云同步、协作、面板停靠与工作区。

## 5. 技术方案

### 5.1 数据模型 v2（已实现）

实际落地的 v2 保持「扁平 clip 字段 + 新增容器」：`transform` / `audio` 不拆子对象，避免一次性重构渲染代码；效果栈留待 Phase 2 再加 `effects[]`。

```json
{
  "v": 2,
  "name": "项目",
  "w": 1920,
  "h": 1080,
  "fps": 30,
  "sampleRate": 48000,
  "media": [
    { "id": "m1", "kind": "video", "name": "a.mp4", "url": "", "dur": 12.3,
      "w": 1920, "h": 1080, "source": "library", "libId": "..." }
  ],
  "tracks": [
    { "id": "v1", "kind": "video", "name": "主视频", "locked": false,
      "muted": false, "solo": false, "hidden": false, "height": 46 }
  ],
  "clips": [
    {
      "id": "c1", "track": "v1", "kind": "video", "mediaId": "m1",
      "name": "a.mp4", "start": 0, "dur": 5, "in": 2, "speed": 1,
      "x": 0, "y": 0, "scale": 1, "rot": 0, "opacity": 1,
      "volume": 1, "muted": false, "fadeIn": 0.5, "fadeOut": 0.5,
      "filter": "none",
      "kf": {
        "opacity": [
          { "t": 0, "v": 0, "ease": "linear" },
          { "t": 1, "v": 1, "ease": "easeOut" }
        ]
      },
      "text": null
    }
  ],
  "markers": [{ "t": 3.2, "name": "章节 1", "color": "#f0b429" }],
  "meta": { "createdAt": 0, "updatedAt": 0, "app": "studio" }
}
```

迁移规则（`migrateProject`）：v1 补 `tracks = defaultTracks()`、`markers = []`、每个 clip 补 `kf = {}`、`sampleRate = 48000`；v2 恒等。`normalizeProject` 再校验：轨道 id / kind 去重、片段 kind 必须与轨道 kind 匹配、关键帧按 `t` 排序去重、`ease` 不在白名单则回退 `linear`。读坏数据回退到 `blankProject()`。

### 5.2 渲染架构

```
媒体源（video/img/text）
  → 解码（播放：HTMLVideoElement；导出：WebCodecs VideoDecoder）
  → 效果链（滤镜 / 蒙版 / 抠像 / 调色）
  → 变换（位置 / 缩放 / 旋转 / 透明度 / 关键帧采样）
  → 合成（轨道顺序 + 混合模式）
  → 输出（预览 canvas / 导出编码器）
```

- **单一 `renderFrame(ctx, project, t, opts)`**：预览与导出只传不同 `opts.scale`，避免两套逻辑漂移。
- **主时钟**：播放时以 `AudioContext.currentTime` 为基准，`rAF` 只负责刷新，音频不会越播越偏。
- **关键帧采样**：`sampleTrack(keys, localT)` 独立纯函数，便于单测。
- **文字**：Canvas2D 绘制到离屏画布再作为纹理，预览与导出一致。
- **性能预算**：1080p30 单帧合成 < 16ms；500 片段时间线滚动不掉帧；标尺与轨道 DOM 复用。

### 5.3 导出

- 优先 `VideoEncoder` + `AudioEncoder`（WebCodecs）→ MP4（需引入 mp4 封装器，放 `apps/studio/vendor/` 并说明来源）。
- 不支持时回退现有 `MediaRecorder` 实时 WebM。
- 音频导出走 `OfflineAudioContext` 离线渲染，保证时长与采样率稳定。
- 导出任务化：准备 → 渲染 → 编码 → 封装 → 下载，支持取消与进度。
- 不在本方案内新增 Electron 主进程 ffmpeg 通道；若后续需要，另立提案。

### 5.4 存储

- 项目 JSON：`localStorage`（小）+ `.hfstudio` 文件导入导出（大）。
- 波形峰值、缩略图、代理、自动保存快照：IndexedDB（复用项目已有 `blob-store` 封装）。
- 自动保存：操作后 650ms 防抖写当前项目；每 5 分钟或每 50 步写一份快照，保留最近 5 份。

### 5.5 UI 结构

- `body.js` 拆成：顶栏 / 素材区 / 监视器 / 检查器 / 时间线 / 弹层六块，仍只导出 `window.STUDIO_BODY`。
- 检查器由「属性 schema + 控件工厂」驱动，新增参数不再手写 DOM。
- 时间线：轨道头独立渲染；片段 DOM 复用池；关键帧编辑器作为时间线子面板。
- 快捷键：集中注册表，支持后续自定义。

## 8. 风险与取舍

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| WebCodecs / H.264 在部分环境不可用 | 无法导出 MP4 | 能力检测 + WebM 回退；导出弹层明确提示 |
| MP4 封装需第三方库 | 体积与许可 | 只 vendor 必要文件，注明来源与许可证 |
| 统一合成器重构面大 | 回归风险 | Phase 0 先做像素一致性对照，保留旧路径一个版本 |
| 长时间线 DOM 过多 | 卡顿 | 虚拟化 + 节点复用 + 标尺限宽（已有） |
| 代理与缓存占空间 | IndexedDB 配额 | 按项目清理、上限与手动清空 |
| 关键帧让撤销快照变大 | 历史内存 | 快照压缩（只存差异）或降低上限 |
| 音频与画面漂移 | 音画不同步 | 以 `AudioContext` 为主时钟，逐帧校正 |

## 9. 完成判据（本方案整体）

- 专业剪辑的日常链路可闭环：导入 → 组接 → 精剪 → 字幕 → 调色/效果 → 混音 → 导出 MP4。
- 预览与导出一致，关键帧、转场、蒙版在两端表现相同。
- 项目可保存、导入、崩溃恢复，素材失效有重链入口。
- `node tools/test-headless.js studio --registry` 全绿，且无固定端口 / 固定路径 / 真实密钥。
- 行为变更同步更新 `apps/README.md` 与本文状态（提案 → 已生效）。

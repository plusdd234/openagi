## 1. 目的

给 DeepSeek 一条**不依赖视觉通道**的精确制图路径：

```
位图 → 线带掩膜（程序算） → 细化成 1px 中线 → 中线折线 + 线宽 + 采样点（文本，带稳定 key）
     → 模型：语义命名 + 控制点重绘（走向/线宽/颜色/顺序）
     → 程序：坐标换算 + Catmull-Rom 拟合 + 落笔 → 栅格化回读 → 指标反馈
```

提取器负责**分布**，模型负责**语义与曲线**，程序负责**拟合与渲染**。

本文要回答的问题只有一个：**这条路径的误差来自哪一层，改哪一层收益最大。**

### 1.1 线稿只是输入：分布 vs 语义与曲线

| 角色 | 提供什么 | 不负责什么 |
|---|---|---|
| 位图（视觉） | 「这是企鹅」、每个部位是什么 | 精确几何、坐标 |
| 提取器（程序） | 哪里有东西、多长、多粗、什么颜色、大致怎么弯（`samples` 12–128 点，RDP 保形抽稀） | 语义、最终曲线形状 |
| 模型（DeepSeek） | 这条线是什么（`name`，中文「主体·部位」）、精确走向（`points` 3–96 个）、线宽、颜色、层级 | 像素读取、坐标换算、曲线拟合 |
| 渲染器（程序） | `0–1000` → 区域像素换算、Catmull-Rom 平滑、描边、回读栅格 | 判断画得对不对 |

对应两个工具：

- `vl_redraw_parts`（**默认**）：模型给 `points` 控制点 + `name` + 样式，程序拟合后替换该条几何。
  坐标口径与 `vl_view_region` 的 `samples` 一致：**相对区域归一化 0–1000**。
  控制点从 `samples` 出发，曲率大处密、直段疏；不给 `points` 时退化为按参考几何复制。
- `vl_draw_parts`（**仅限**「几何已经对、只想改粗细颜色顺序」）：只传 key 与样式，不传坐标。

硬约束：实线只能由模型调用工具产生。提取完成只画淡虚线参考层，否则画布上的实线是程序画的，
监督就失去意义（状态栏的 `已描绘 x/y` 就是这条约束的可观测形式）。

## 2. 为什么线稿层与区域层必须分开

> 2026-11-16 补充：闭合轮廓已支持填色，但「线」与「区域」仍是两种对象、两套指标，不能混算。

位图里没有「线」，只有覆盖率。三种轮廓是不同的几何对象，必须分开：

| 概念 | 数学对象 | 面积/指标 | 说明 |
|---|---|---|---|
| 区域边界 | 零宽闭合曲线（crack boundary） | 面积 = 像素数，IoU 有意义 | 填充层的对象 |
| **中线 + 宽度** | 骨架折线 + 每点半径（扫掠圆） | Chamfer + 覆盖率 | **线稿层的对象** |
| 描边带 | 中线按 r 膨胀（Minkowski 和） | 面积为 2r×长度 | 渲染时的实际像素 |

把中线塞进 IoU 里必然误判：一条居中描边的线永远有一半线宽落在「区域」外，
凹角还会自交。所以填充层整套指标（IoU / ΔE / 边缘 F）已随之移除。

那「轮廓模式」算哪一类？它取的是第一条（区域边界），但**依然只画不填**：
每条边界是一圈 stroke，没有填充、没有 evenodd。它存在的理由是——
文字和实心笔画的中线在交叉处必然断开，画出来是一堆短线段；
轮廓是闭合的，单独看就能认出字。轮廓模式的回读参照是**掩膜边界像素**，
判定的是「边界跟得准不准」，不是整块面积的 IoU。

另一个硬约束：厚度低于约 1.5px 时线稿在像素上不成立（抗锯齿只留下覆盖率），
提取只能得到断续的 1px 骨架——这是路线边界，不是调参问题。

## 3. 已实现（线稿层基线）

| 能力 | 位置 | 说明 |
|---|---|---|
| 形态三档 | `extractRect()` / `skelStats()` | `auto`（默认）/ `contour`（每字一圈闭合环）/ `center`（中线 + 线宽）。`auto` 先算骨架与距离变换，只在「骨架长度 / bbox 周长 ≥ 0.45 且中位线宽 ≤ 2.5px」时判为**细线稿** → `center`；其余是实心区域 → `contour`。判据值随结果返回（`auto: {ratio,w,short,pick}`） |
| 轮廓填色 | `fillGroups()` / `fillOne()` | 闭合环默认按区域填充（孔洞按包含关系挂到外轮廓，用 `evenodd` 挖掉）；中线仍只描边。UI 的「填色」可关掉退回空心描边 |
| 轮廓追踪 | `traceContours()` | 沿掩膜边界建边，按「前景在右手边」连成闭环；对角相接处优先右转，避免把相邻字形缝成一个 |
| 取线四模式 | `buildLineMask()` / `colorExtract()` | `dark`（暗像素）/ `edge`（Segmenter 梯度墙）/ `auto`（按暗像素平均厚度 <5.5px 判为线稿）/ `color`（色块）。`auto` 只在 dark / edge 之间选，多色图要手动切色块（P12） |
| 色块模式 | `colorSeg()` / `mergeNoise()` / `mergeIslands()` / `regionLoops()` / `fillRegion()` | 分件（Segmenter 洪泛 + 邻接合并 + 碎块归并 + 墙像素归并）→ 每块取外轮廓 + 内孔 → 用区域平均色、按面积从大到小逐块填充（painter's algorithm）。贴边且与主背景色接近的块判为背景，不填。小碎块**分三类**：亮度夹在邻居之间的过渡色（抗锯齿 / 压缩噪点）并进颜色最近的邻块；被包住且亮度是局部极值的小块是真实细节（瞳孔、高光），保留（`isDetail()`）；被黑线隔开、与某个至少 4 倍大的块**同色且包围盒相距 ≤4px** 的小岛并进那个块（`mergeIslands()`）——围巾在下巴露出的一小块红属于围巾，不是「舌尖」 |
| 曲线落笔 | `regionLoops()` / `fitBezLoop()` / `bezPath()` | 色块边界是三次贝塞尔**拟合**，不是折线也不是插值：`rdpClosed` 抽稀后按最小二乘求每段 `c1/c2`，误差超容差就二分；闭环接缝挪到拐角最大的点，避免在平滑段留折痕。容差 `min(bw,bh)×0.05`（clamp 0.5~10px）——大块的像素台阶被平均成直线 / 弧，眼睛和脚掌仍保留形状。落笔用 `bezierCurveTo`，每块 2~8 段 |
| 分图层 | `S.layers` / `groupedParts()` / 图层列表 | 每个语义组是一层，带名字、组色、包含块数和显示开关；按面积从大到小逐层落笔。左侧列出全部图层，点一行可单独隐藏，用来核对单个部位，而不是只能看一张糊在一起的画 |
| 控制点编辑 | `drawAnchors()` / `nearestAnchor()` / `S.ckpt` | 「控制点」开关打开后画布上画出所有锚点，直接拖动即改曲线；改动只影响几何，旧指标清空等重新回读。锚点就是 `path` 里的点，与 `vl_redraw_parts` 的控制点同口径 |
| 语义分组 | `groupParts()` / `groupedParts()` / `vl_group_parts` | 模型把碎块归到「部位」并命名、`drop` 噪声；组名直接写入该组每条线的 `name`（`source='model'`，用户手改过的名字不覆盖）——参考线列表与锚点标签显示的是「企鹅·白色肚皮」，不再退回 `白·中中`。**同级碎块各自填，只有整个套在另一块里的成员才当孔洞**（否则两只脚并组时右脚会整块消失）。组色默认为空＝沿用每块实测原色；给定组色与实测平均色差 >60 时**拒收**并在 `colorFixed` 回报——语义只能决定归组与遮挡顺序，不能改写测量出来的颜色 |
| 语义自检 | `semanticCheck()` / `vl_check_semantics` | 返回每组块数、未分组块（含面积/bbox）、重复归组、未命名组、已 drop 数、`clash`（组内颜色跨度 >90，说明把两个部位并成一组）、`colorFixed`（被拒收的组色）。与 Chamfer 分工：指标回答「画到了」，它回答「画对了没有」 |

| 稳定 key | `stableKey()` | 长度/中点/色相桶组成的指纹，重提取后命名不错位 |
| 语义命名 | `nameUnknown()` / `defaultName()` | 三层优先级：用户手改 > 模型 > 启发式。**启发式不是语义**：色块默认名只有测量值「色·位置[/孔数]」（如 `白·中中·1孔`），线稿默认名是 `线段N`，`source='heuristic'`、`conf=0.3`。真正的语义（围巾 / 眼睛 / 白肚）只能由模型经 `vl_group_parts` / `vl_name_parts` 写入 `S.lexicon`（`source='model'`）——`autoDraw` 复制路径本来就不带语义，要看部位名必须走监督重绘 |

### 指标口径（重要，改口径等于改结论）

1. **参照掩膜 = Segmenter 的前景掩膜（`seg.fg.mask`），不是亮度阈值。**
   前景 = 从图像边界泛洪吃不到的部分；否则浅色实心块会被判成背景，
   覆盖率指标直接失真。
2. **Chamfer 双向算**：原图掩膜 → 描绘掩膜的最近距离（漏线），反过来是多线。
   `chamferP95` 用来看「少数几条错得很远的线」，均值会把它稀释掉。
3. **召回/精度用 1.5px 容差判定命中**，不要求逐像素重合——线宽本身是估计值。
4. **不统计 ΔE / IoU**：彩色线只比较颜色是否在同一色相桶，颜色误差不进入主指标。
5. **中位线宽是估计值**，不是真值：`2×dt` 是「到最近背景像素中心的距离」，
   对 1px、3px 这类奇数厚度会系统性偏小半像素（见 P1）。

| 形态 | 段数 | 闭合 | 长度 <20px | Chamfer / P95 | 召回 / 精度 |
|---|---|---|---|---|---|
| 轮廓 | 72 | 72 | 22 | 0.066 / 1.0 | 0.9956 / 0.9997 |
| 中线 | 66 | 0 | 59 | 2.297 / 12.0 | 0.6859 / 0.9861 |

在「只看重绘」下，轮廓是完整的空心字，能直接读出三行文字；
中线是一堆断笔（`IIl→ seed ∫`）。这就是「描绘出来是短线段」的来源：
不是参数没调好，而是中线在笔画交叉处必须断开，而文字几乎每个字都有交叉。

距离变换的方向已修正：`distTransform` 求的是「到最近 0 像素」，
所以回读时先把两边的掩膜取反，得到「到最近的线有多远」。
修正前 chamfer 实际算的是「被覆盖」（完全漏画反而得 0），指标方向是反的。

同一张演示图在中线口径下三种取线模式的段数也不同：`edge` 32 段、`dark` 16 段、`auto` 32 段。

**控制点重绘（程序侧，不含模型判断）**：取演示图最长的一环（长度约 796px），

### 4.3 分辨率收敛（2026-11-15）

**A 组（有真值）**：把 1920 企鹅缩到各档再提取，坐标归一化后按 512px 画布计算与 1920px 结果的偏差。

| 输入 | 环数 | 中位偏差 | P95 |
|---|---|---|---|
| 37px | 2 | 8.72px | 30.99px |
| 74px | 3 | 3.68px | 19.10px |
| 148px | 5 | 5.72px | 8.85px |
| 296px | 8 | 3.07px | 4.55px |
| 592px | 8 | 1.58px | 3.00px |
| 1184px | 10 | 1.02px | 2.19px |
| 1920px | 10 | 0 | 0 |

环数在 592px 才稳定到 8、1184px 才到 10；37px 只剩 2 环——**低分辨率丢的是拓扑，不只是精度**。
偏差不随分辨率单调下降（148px 比 74px 差），因为环数在变，是「跟另一组拓扑」比。
结论：提取下限取 600px，复杂图形取 1000px+；低于 300px 应直接提示「分辨率不足」。

**B 组（无真值）**：把 37px 图标放大到 74/148/296/592 再提取，环数是 9 → 10 → 30 → 0。
放大不恢复信息，还会因插值改变暗度分布让阈值判断失效（592 档直接提不出任何环）。
所以「先归一化到高分辨率再重建」不能当精度手段；它只能统一口径，且要接受它本身会引入新的失效模式。

真实素材对照（QQ 企鹅图标 75×79，实心图标，没有「线」；下表是**中线模式**）：

| 取线 | 段数 | Chamfer | 召回 | 精度 |
|---|---|---|---|---|
| `auto`（判成 dark） | 11 | 5.042 | 0.464 | 0.991 |
| `edge` | 17 | 1.839 | 0.644 | 0.981 |

结论：实心图标里暗像素是一整块，中线只能穿心而过，指标不达标——
**这类图应该用轮廓模式**，中线模式只适合有描边的线稿与手绘单线。

历史对照（填充层版本，仅存档，指标不可与上表比较）：QQ 企鹅图标 75×79，

### 4.4 曲线参数化对照（D 组，2026-11-15）

问题：重绘的残差到底是「控制点不够」还是「插值器过冲」？
做法：同一批参考线、同一份 `samples`，只换拟合器参数化（均匀 α=0 / 向心 α=0.5），
跑「全量采样重绘 → 回读」。

| 图 | 参数化 | 环数 | Chamfer | P95 | 召回 | 精度 |
|---|---|---|---|---|---|---|
| 演示图 480×360（auto→dark） | 均匀 | 4 | **1.036** | 4.00 | **0.759** | **0.611** |
| 同上 | 向心 | 4 | 1.422 | 5.83 | 0.631 | 0.531 |
| 人像 355×241（auto→edge） | 均匀 | 109 | **0.992** | 3.83 | **0.776** | **0.840** |
| 同上 | 向心 | 109 | 2.008 | 5.41 | 0.723 | 0.830 |

同时把采样预算从 `周长/24` 提到 `周长/4`（演示图 23 → 25 点），Chamfer 只从 1.09 降到 1.04。
直接复制几何（不重绘）时 Chamfer 0.001。三条一起说明：

1. **插值器不是瓶颈**。向心参数化在两种图上都更差，已回退，不做保留。
2. **点数也不是此时的瓶颈**。RDP 在 114 个顶点里本来只保留 25 个保形点，加大预算取不到更多点。
3. 残差全部来自「少量折点 + 程序猜测每段切线」。也就是说，缺的既不是点也不是样条类型，
   而是**每段该往哪转**——这正是模型能给、程序猜不到的信息（对应 L20）。

### 4.5 端点 + 手柄（B / C 组，2026-11-15）

实现（`redrawParts` 的 `form:'bezier'` 分支）：

- 输入：`start` + `segs[{c1,c2,end}]`，坐标仍是**相对区域归一化 0–1000**。
- `breaks`：`viewRegion` 给每条线的切段建议，目标段长 60px、2–16 段，
  段界优先吸到转角最大的顶点（`vertexTurns`），并强制弧长严格递增。
- 手柄缺省时走 C 组：方向取参考线在段的起收点切向，只解两个长度标量（2×2 法方程）。
- 手柄长度上限 0.85×弦长，超过即夹紧并计数（`clamped`），否则三次贝塞尔会在段内自交出环。

实测（演示图 480×360，`contour / auto`，4 环；最长环 663px）：

| 配置 | 最长环 | Chamfer | 说明 |
|---|---|---|---|
| A 组：19 点 + 均匀 Catmull-Rom（全量） | 19 锚点 | 1.09 | §4.4 的同一条流水线 |
| C 组：最长环改端点 + 手柄（12 段，程序拟合） | 12 段 | **0.989** | 其余 3 环保持 A 组结果 |
| B 组：模型给超长手柄 | 12 段 | — | `clamped 20`，全部被夹回 0.85×弦长 |

对参考线的最大偏差（单环，程序拟合手柄）：

| 环长 | 修前（按最近顶点取子路径） | 修后（弧长空间投影） |
|---|---|---|
| 663px | 13.44 | **5.92** |
| 435px | 6.50 | **5.51** |
| 411px | 10.74 | 10.45 |
| 147px | 8.12 | **3.40** |

三条结论：

1. **切向必须按弧长定位，不能按最近顶点定位。** RDP 之后顶点间距可达 12px
   （411px 的环只有 35 个顶点），最近顶点最多偏半格；而轮廓在窄颈处自相近，
   全局最近点还会跳到环的另一侧——实测出现过 `chord 51px / 弧长 320px`，
   最小二乘解出的手柄长度直接顶到夹紧上限。改成「弧长空间 + 向前窗口」后，
   该段的弧长回到 65px，钳制次数从 2 降到 0。
2. **60px 是段长的下限。** 120px、最多 8 段时，一段三次贝塞尔跨过拐角，C 组 Chamfer 3.95；
   收到 60px、最多 16 段后降到 0.989。再短只是增加段的个数，不再降 Chamfer。
3. **尖角是表示差异，不是实现 bug。** C1 连续的三次贝塞尔无法在段内表达尖角，
   拐角落在段内时单点偏差仍可达 5–13px（Chamfer 因为按面积/线带算，被稀释到 1px 以内）。
   要真正复刻尖角，只能在拐角处断开段（`breaks` 已经在做），或者允许段内 G0 折角。

**两处必须记住的实现教训：**

1. **提示词里的口径冲突，模型站在开头那条。** 第一次跑 bezier 时，模型 5 次重绘全部传 `points`，
   一次 `segs` 都没有：开头的硬规则写着「points 是控制点、samples 原样传回」，
   末尾的分组说明压不过它。改成把第 1、2、5 条与工具描述一起按分组替换（`GEOM` / `FORM_TOOL`）后，

2. **复盘要用工具调用要，不要让它自由续写。** 这台中转在无工具的自由续写上会退化成

1. 第一次试的是中线：把实心字判成笔画网络，16 条中线 + 15px 线宽画出来是一堆圆头面条，

2. 最终修正：实心区域应当**保留闭合轮廓并填色**，而不是退化成中线。

   `contour` 默认填色，孔洞按包含关系挂到外轮廓上并用 `evenodd` 挖掉。
   演示图判据 `ratio 0.83 / w 20 / 短边 143` → 实心区域 → `contour` + 填色；
   54×48 图标 `ratio 1.04 / w 2.83` → 同样 `contour` + 填色。UI 的「填色」可关掉，退回空心描边。

**修复过程中暴露的两个运行级问题**：

1. 模型会在「24 段·center / 5 段·contour」之间反复重提取，8 轮全部用完仍 0 条描绘。
   现在一条线都没画时改口径会被拦截，只有 `force:true` 才放行；首次真实运行因此仍 0 条，拦截后第二次才画出全部参考线。
2. 模型在校验后 `force` 重提取，把已画的线全部清空，随后请求超时。
   现在循环结束时画布为空会自动回滚到 Chamfer 最好的一轮；快照保存整份线段几何，
   即使 `force` 后 key 全变也能还原。

指标：Chamfer 0.333、召回 0.976、精度 0.953 —— 三个数都很好，但视觉上不成立。原因有两层：

1. 这张图是**填色图标**，「25」是白色**孔洞**而不是线。当时只有空心描边，于是画成双层蓝框 + 25 的轮廓，填不出白色数字。
   填色层已经落地（外轮廓 + 孔洞 `evenodd`），这条已具备修复条件，但需要重跑验证。
2. 54×48 下边界只有 1px，放大 8 倍后 1px 抖动就是 8px 毛刺；同一块圆角方块的软边被当成两条边界各描一次
   （`l142` / `l129`，bbox 只差 2px），填色时会变成两圈外轮廓叠在一起。这条仍然未解决。

**结论**：指标只能证明「边界/区域画到了」，不能证明「看起来对」。图标与扁平插画需要**填色层 + 孔洞**（已实现），
还要解决小尺寸下同一边界被抽成两圈的问题；真实运行里模型「改坏后不回滚」是比曲线拟合更贵的误差来源。

### 4.8 案例 3：多色图标（67×65 企鹅）· 色块模式对比（2026-11-16）

同一张图、同一账户、同一提示词，只换取线源，各跑一次真实运行（图放大 6 倍后输入）：

![企鹅图标：原图 / 暗线填色 / 色块原色](assets/visionlab-icon-color-compare.png)

| | 改良前：暗线 + 单色填色 | 改良后：色块 + 原色填充 |
|---|---|---|
| 参考线 | 7 条（全是深色区域） | 15 条（每个色块一圈） |
| 模型动作 | `view → redraw ×1 → check → finish`（7/7 重绘，带语义名） | `view → draw_parts ×2 → check → finish`（15/15 原样复制） |
| 指标 | Chamfer 0.008 · 召回 0.999 · 精度 0.995 | Chamfer 0.193 · 召回 0.953 · 精度 1 |
| 画面 | 黑白反相：深灰底被填成黑，企鹅与白圆变成洞 | 白圆 / 黑身 / 白肚 / 红围巾 / 黄嘴黄脚齐全 |

改良前的指标几乎满分，画面却完全不可用——因为参照掩膜本身就是错的：

1. `buildLineMask` 固定 `mode:'light'` + `background 238`，只把亮度 >238 当背景。
   这张图的画布是深灰（亮度≈60），从四边泛洪时整块被判成前景。
2. 取线只走「暗像素」掩膜，红色（`#e02424`）、黄色（`#f2ab23`）都不在掩膜里，零提取。
3. 填色只有一种墨色（`inkColor` 会把浅色压暗），即使拿到多色区域也会被涂成同一色。

改良后新增 `color` 取线源：Segmenter 分件 → 每块取外轮廓 + 内孔 → 区域平均色 →
按面积从大到小逐块填充（painter's algorithm）。贴边且与主背景色接近的块判为背景、不填；
面积 < 0.1% 的小碎块不进参考线（26 块筛到 15 块，缺口就是召回少的那 4.7%）。

剩余问题：

1. `auto` 仍只判 `dark / edge`，多色图要手动把取线源切成「色块」（P12）。
2. 「只看重绘」在色块模式下用浅灰底（`#eef1f5`），否则白色圆板会和白底融在一起。
3. 色块模式下模型按设计用 `vl_draw_parts` 原样复制，不再产出语义名；要保留命名需让它对色块单独调 `vl_name_parts`。
4. 脚趾之间的抗锯齿暗带会被当成一个真实色块（图中脚间的褐色条），属于分件噪声。

### 4.9 案例 4：语义分组 · 让「围巾像围巾、眼睛像眼睛」（2026-11-16）

承接 4.8：色块模式的分块是对的，但模型只是把 15 块逐块复制，画面里「脚间暗带」「翅根灰条」和眼睛
平铺在一起，语义上是乱的。于是加一层「分组」：模型把碎块归到部位、命名、`drop` 噪声，
程序按组面积降序落笔。同一张企鹅图（6× 放大到 402×390）真实运行：

| 轮次 | 流程 | 结果 |
|---|---|---|
| 第一次（`vl_group_parts` 只落笔一次、组色覆盖原色） | `view → group → check → view ×4 → group` | 8 轮耗尽、**0 条描绘**、Chamfer 1e9——模型把「分组」当成分析动作，没意识到要落笔 |
| 第二次（分组即落笔） | `view → group → check → finish` | 15/15 落笔，Chamfer **0.073**、召回 **0.980**、精度 1，15 个部位全部命名；但眼睛在画面上是深色 |
| 第三次（组色不得改写测量值 + 部位判据给 tone/where/holes/area） | `view → group → check → finish` | Chamfer **0.193**、召回 0.953、精度 1；眼睛恢复成白色眼白，围巾（含垂下的尾端）、喙、双脚成形 |
| 第四次（碎块分「过渡色 / 局部极值」两类） | `view → group → check ×3 → finish` | 24 块（含 34px 的瞳孔块），22/24 落笔，Chamfer **0.191**、召回 0.949、精度 1；**双眼都有瞳孔**，眼白不再是被切碎的窄条 |

「眼睛发黑」的根因不在提取，也不在渲染，而在**语义把测量值改写了**：

1. 模型给「企鹅·左眼/右眼」写 `#f7f7f7`，却把真正的两个白眼块（`tone=白`、在头部、`area` 231/185）
   命名成「瞳孔」并给 `#111111`。
2. 旧实现无条件采用组色 → 白眼块被涂成黑色 → 眼睛变成两个黑点。
3. 修法不是改提示词求模型别错，而是**把颜色从语义层剥出去**：颜色只来自实测（区域平均色），
   模型给的组色与实测差 >60 就拒收，`colorFixed` 里回报「给了什么、实测是什么」。
   模型名错了最多少一个名字，画面颜色不会跟着错。

同一轮真实运行还暴露了两个实现问题，都已修：

- `drop` 写在**顶层**（`{"drop":[…],"groups":[…]}`）时被静默忽略，`未分组` 一直清不掉，
  模型反复重分组直到轮次耗尽。现在顶层与组内两种写法都认。
- 并组时「除最大环外都当孔洞」会把并列的碎块挖空：两只脚并成一组时，右脚整块消失。
  现在只有「整个套在另一块里面」的成员才当孔洞，同级成员各自填。

眼睛的第三个问题（瞳孔丢失）与语义无关，是**面积下限把细节当噪点删掉了**：

1. 402×390 输入里瞳孔只有 34 像素（`rgb 4,4,4`、`bbox` 6×6），块下限是 `w*h*0.001 ≈ 157`；
2. 周围看得见的又全是 30 多像素的抗锯齿过渡块——单看面积，瞳孔和噪点无法区分；
3. 旧口径只有一刀切的 `cleanupSmall(260)`：要么把瞳孔并进眼白（瞳孔消失），要么全留（满屏碎块）。

修法按**亮度是不是夹在邻居之间**分类：过渡色必然是「两个邻居的中间值」，真实细节必然是「局部极值」。

- `mergeNoise()`：面积不够当块的色块，亮度夹在邻居之间 → 并进颜色最近的邻块，反复几轮直到稳定；
- `isDetail()`：不贴画布边、不邻接背景、且亮度比所有邻居都暗或都亮（差 >25）→ 保留。同一判据同时用在
  `colorExtract()` 的块列表上，所以瞳孔既不会被并掉，也不会因为面积不足进不了参考线；
- 效果：企鹅图 15 块 → 24 块，多出来的正是瞳孔 / 高光这类真实细节，眼白也从被切的窄条变回完整色块。

### 4.10 案例 5：「这看起来是像素图」→ 曲线落笔 + 可拖控制点（2026-11-16）

瞳孔补回来之后，只看重绘的图仍然是一圈圈 6px 台阶。原因不在分件，而在**几何与落笔口径**：

1. 色块边界取的是像素裂缝（crack boundary），点距只有 1px，描出来就是逐像素折线；
2. 填色用的是 `lineTo`，曲线也被画成多边形；
3. 输入是 67px 图标放大 6 倍，台阶宽度就是 6px，靠 0.5px 的抽稀容差完全消不掉。

三处一起改：

| 环节 | 改法 | 参数 |
|---|---|---|
| 抽稀 | `regionLoops()` 里 `chaikin(2)` → `rdpClosed(eps)` | `eps = clamp(max(简化, min(bw,bh)×0.06), 0.4, 16)`，按**块**的大小给：大块要 12px 才消得掉 6px 台阶，小块（眼睛、脚趾）给大了直接抹成斑 |
| 落笔 | 新增 `curvePath()`：锚点按**向心** Catmull-Rom（α=0.5）采样后描边/填色 | 色块填色、色块描边、参考虚线都走它；轮廓模式（文字）仍是折线，尖角不能被抹圆 |
| 编辑 | 顶栏「控制点」开关 → 画布显示锚点，拖动即改 | `drawAnchors()` / `nearestAnchor()`；锚点与 `vl_redraw_parts` 的控制点同口径 |

第一版做完是**扭曲**的，三个原因都在「平滑过头」，已逐个改掉：

1. **均匀参数化 Catmull-Rom 在锚点疏密不均时会打结 / 鼓包**。抽稀后的锚点正是直段一个点、
   弯处一串，均匀参数化会让曲线甩出去再绕回来——这是扭曲的主因，换成向心参数化后消失。
2. **锚点级拉普拉斯平滑**（每个点往邻居中点拉 2 轮）会持续内缩，小块直接被拉没、大块整体变形，
   已删除；台阶交给 `rdp` 的容差处理，曲线交给向心 CR。
3. **容差按整图形尺寸一刀切**：402px 图上给 3px，对 300px 的大块不够（留台阶），对 20px 的眼睛又
   太高（抹平变形）。改成按块包围盒给，才有「大块平滑、小部位保形」。

效果：企鹅图仍是 24 块，每块 6~17 个控制点，只看重绘从「像素拼图」变成连续曲线造型；
Chamfer 0.196、召回 0.952、精度 0.998（早前逐像素折线版是 0.191 / 0.953）。

### 4.12 案例 7：围巾企鹅图标 · 小图先补像素再矢量化（2026-11-16）

输入是 37×36 的像素风图标（腾讯企鹅，红围巾）。直接跑会失败：原图放大 10 倍后抗锯齿过渡色
被逐条切开，变成 **152 个色块**，模型光看完就耗尽轮次、上游超时，0 条落笔。

预处理（只影响输入，不改提取器）：

1. 裁掉图标外框，只留白底 + 企鹅（28×28）；
2. 按色相把每个像素归到 4 个平面色（白 / 黑 / 红 / 橙），去掉抗锯齿过渡色；
3. 贴边 2px 刷白，清掉裁切口留下的 4 个黑色圆角碎点；
4. 最近邻放大 10 倍（280×280），让眼睛（原 2~3px）和脚掌（原 2~4px）高于 `minArea`。

结果：13 个色块，一次归组全部落笔。

| 项 | 值 |
|---|---|
| 工具链 | view → group → check → finish |
| 落笔 | 13/13，Chamfer 0.016 · 召回 0.9967 · 精度 0.9607 |
| 语义名 | 身体与头部黑色轮廓 / 红围巾 / 左右翅膀 / 橙色喙 / 左右眼白 / 左右脚掌 / 围巾左右橙穗 / 围巾内侧橙块 / 舌尖红点 |
| 求的三项 | 围巾（红色带 + 下垂巾尾 + 两侧橙穗）、眼睛（两块眼白，瞳孔由黑色区域的孔洞挖出）、脚掌（左右橙色蹼）全部成形 |

两条可复用结论：

- **小图像素风**要先「补像素再矢量化」：直接放大原图只会把抗锯齿噪点放大成上百个碎块；
  量化成平面色再放大，碎块数从 152 降到 13。
- **白肚皮是背景而不是部件**：原图两腿之间是通的，白肚与图标白底连成一片，
  所以它作为黑色区域的孔洞挖掉；画白底上没问题，画在灰底画布上会显示成画布色。

### 4.13 案例 8：舌尖幻觉 / 真贝塞尔 / 分图层（2026-11-16）

上一轮交付被指三处问题，逐条对应到代码：

| 反馈 | 原因 | 处理 |
|---|---|---|
| 「哪来的舌尖」 | 喙下方 1 个红像素与围巾同色、被黑线隔开，分件后成了独立小块，模型只能硬起名 | `mergeIslands()`：面积 < 2.5×minArea、与某个 ≥4 倍大的**同色**块包围盒相距 ≤4px 的小岛并进该块 → 红点并入围巾，13 块变 12 块 |
| 「不是矢量贝塞尔平滑曲线」 | 色块边界走 `chaikin(2) + rdpClosed + 向心 Catmull-Rom 采样`，是折线加密，像素台阶被保留 | 换成三次贝塞尔**最小二乘拟合**（`fitRun`/`fitBezLoop`）：弦长参数化 → 两端切向 → 解 `alpha1/alpha2` → 误差 > tol 二分（depth ≤14），落笔用 `bezierCurveTo` |
| 「没有分图层」 | 只有一张合成图，部位无法单独核对 | 每个语义组是一层（`S.layers`：名字 / 组色 / 块数 / 开关），左侧图层列表点一行即隐藏该层，`paintOps` 按 `S.hidden` 过滤 |
| 「像强制提取像素融合」 | 分组后直接落笔的是像素台阶边界 | 提示词口径改为**必须重画**：`vl_group_parts` 落笔的只是参考，必须再调 `vl_redraw_parts` 按部位给 8~20 个控制点重画；`samples` 只用来定位 |

闭环拟合的数学坑：`fitBezLoop` 把首点补到末尾，`fitRun` 里 `p0 === p3` → 弦长为 0 →
若直接出直线会得到四个相同点，整块消失（探针报「色块重绘覆盖率 0/0」「Chamfer 1e9」）。
修复：弦长 < 1e-6 时在中点切成两段递归；同时把闭环接缝旋到转角最大的点，避免折痕留在平滑段。
`groupedParts()` 合成部件时必须一并透传 `bez / holeBez / tol`，否则分组后又退回折线。

两条渲染路径的实测（同一张围巾企鹅，280×280）：

| 路径 | Chamfer | 召回 | 精度 | 观感 |
|---|---|---|---|---|
| 程序拟合（`vr_auto`，不调模型） | 0.264 | 0.9476 | 0.9736 | 曲线是真贝塞尔、分图层，但**仍是像素轮廓的平滑版**：源图放大 10 倍后台阶宽 10px，拟合容差只有 5.45px，台阶保留，看起来「歪歪扭扭」 |
| 模型重画（`vol_live`，13/13 落笔） | 0.023 | 0.9952 | 0.9683 | 曲线平滑、分图层，但**形状走样**：围巾变厚、翅膀下垂、眼睛变形 |

想把 10px 台阶真正抹掉，试过两条路，都回退了：

| 尝试 | 结果 | 为什么不行 |
|---|---|---|
| RDP 容差抬到 0.85×台阶（≈8.5px） | 台阶消失，但头顶圆弧被砍成一条直线，脚掌只剩 3~4 个点、几乎消失 | RDP 只挑点不做平滑，大容差等于丢细节 |
| 按台阶宽度做环形滑动平均（窗口 = 10，2 轮）再抽稀 | **Chamfer 0.264 → 5.437，召回 0.9476 → 0.6555** | 窗口平均让边界整体内缩约半个台阶；厚度只有 10px 的脚掌被内缩掉一半 |
| 缩回 28×28 原尺寸再矢量化 | 提取出 0 块 | 原尺寸下眼睛/脚掌只有 6~20px，低于 `minArea`（24），需要改小图专用阈值 |

结论：分辨率上限在输入，不在渲染。28px 像素源只有像素轮廓这一份事实——台阶宽 10px，
任何能抹平它的容差（≥5px）都会一起抹掉 1~2 源像素的细节。程序拟合把它平滑化、
模型重画把它语义化；要「干净且不失真」需要更高分辨率源图，或让模型只在程序给的控制点上做
小幅修正（当前 `vl_redraw_parts` 是全量替换，没有「保形」约束）。

| P6 | 命名只看几何与颜色 | 语义必然猜错，认不出主体 | 企鹅图被命名为「主体外轮廓（内层闭环）」「左侧小环」 |

| P9 | 轮廓模式对细描边出双边缘 | 一条线被画成同形两条（宽度 1） | 企鹅脚/嘴各出现长度几乎相同的两条环；模型主动跳过 5 条 |
| P10 | 全量采样重绘比直接复制差两个量级 | 程序拟合本身吃掉精度（0.001 → 1.04） | §4.4：加预算与换参数化都无效，残差在切线方向；§4.5：把最长环换成端点 + 手柄后 1.09 → 0.989，印证残差确实在切向 |
| P11 | 填色层的残余问题：小尺寸同一边界被抽成两圈 | 1px 软边被当成两条边界，填色时两圈外轮廓叠加 | 54×48 图标仍待重跑；轮廓填色本身已落地（§3、§4.7） |
| P12 | `auto` 不会选色块模式 | 深底多色图（图标 / 扁平插画）默认走 `dark`，整块底被当前景，结果黑白反相且彩色部件全丢 | 67×65 企鹅图标：`auto` 判 `dark`，7 条轮廓全是深色区域，红围巾 / 黄嘴 / 黄脚零提取（§4.8） |
| P13 | 语义层能改写测量值 | 模型给白眼块写 `#111111`，眼睛直接变黑——名错一次，画面错一片 | 语义分组第二次真实运行（§4.9）；现改为组色偏离实测 >60 即拒收，颜色只来自测量 |
| P14 | 面积下限把细节当噪点（已修） | 瞳孔 34px 低于块下限 157，`cleanupSmall(260)` 直接并进眼白；反过来全留则满屏 30px 碎块 | 402×390 企鹅图：改为「过渡色归并 + 局部极值保留」后 15 块 → 24 块，含瞳孔块；第四次真实运行双眼有瞳孔（§4.9） |

## 6. 改良方案枚举

分四层。每条都写清楚「改哪里、赌什么、怎么算赢」。

### A. 提取层（纯程序，成本低，优先做）

| 编号 | 方案 | 改动点 | 假设 | 预期 | 风险 |
|---|---|---|---|---|---|
| L1 | 线宽偏置修正 | 线宽 = `2×median(dt) + 0.5`，或按掩膜面积/骨架长度反解平均宽度 | P1 是估计口径问题，不是数据问题 | 召回 0.918 → >0.95，线宽误差 ≤0.5px | 细线（1px）会偏粗 |
| L2 | 端点补偿 | 骨架两端各沿切线延长 `width/2` | P2 来自细化收缩 | 端点 Chamfer 下降 | 交叉处会多出一小截 |
| L3 | 交叉点合并 | 距交叉点 < 2×宽度 的短段合并成一条折线，或标 `junction` 属性 | P3 是断线策略过激 | 段数下降 20–40%，召回不降 | 合并可能连错线 |
| L4 | 分块自适应模式 | 按 64×64 网格统计厚度，逐块选 dark/edge | P4 全局均值掩盖局部差异 | 混合图召回提升 | 块边界线可能断开 |
| L5 | 提取前超分 | 短边 <160 时 ×3 Lanczos 后再提取 | P5 是采样不足 | 短图骨架连通性提升 | 不增加真实信息，Chamfer 上限不变 |
| L6 | 毛刺剪枝 | 长度 < 3×宽度 且仅一端相连的骨架段直接丢 | 细化会在粗线边缘长毛刺 | 碎段减少，精度上升 | 真实短线（眉线）被误删 |

### B. 表示层（改给模型看的东西）

| 编号 | 方案 | 改动点 | 假设 | 预期 |
|---|---|---|---|---|
| L7 | 线稿摘要裁剪 | 只给 top-24 段 + 其余折叠成「N 段短碎线」统计 | token 与干扰同时下降 | 轮数不变，误判减少 |
| L8 | 归一化坐标锚 | bbox 同时给「区域像素」和「0–1000 归一」两套 | 模型对相对位置判断更稳 | 顺序/线宽决策更准 |
| L9 | 宽度分档 | `width` 只给 0.5/1/2/3/5/8 六档 + 实际值 | 模型对连续数值不敏感 | 更少无意义的线宽微调 |
| L21 | 填色层（图标 / 扁平插画） | **已实现**：闭合轮廓按区域填充，孔洞按包含关系挂到外轮廓 + `evenodd`；UI 可关「填色」退回描边 | P11：实心图标/实心字需要整块区域，不能只描边 | 演示图「字 A」已接近原图（§4.7）；54×48 图标待重跑（双边界问题仍在） |

### C. 模型层（改提示与流程）

| 编号 | 方案 | 改动点 | 假设 | 预期 |
|---|---|---|---|---|
| L10 | 命名先行 | 描绘前强制 `vl_name_parts` | 语义名能帮助判断该粗该细 | 线宽分配更合理 |
| L11 | 分层描绘 | 固定「结构线 → 轮廓线 → 细节线」三段 order | 模型排序不稳定 | 叠压关系错误下降 |
| L12 | 两段式 | 第一轮只画长度 top-10，校验后再补细节 | 一次画全容易刷错线宽 | 首轮指标更高，轮数不增 |
| L16 | 控制点预算 | `vl_redraw_parts` 的 `points` 分 12 / 32 / 64 / 96 四档，其余不变 | 点数要随周长与曲率走，不能固定 32 | 找到「Chamfer 达标」的最小点数，降低输出成本与出错率 |
| L17 | 顺序复原 | 按参考线弧长给模型点排序，返回 `reordered` | P8 是排序问题，不是几何问题 | 点对顺序错时也能贴合（实测 0.02px） |
| L18 | 保形抽稀（已采用） | 用 RDP + ε 二分，在预算内取顶点，再补边长中点 | P7 的误差来自均匀采样漏拐角 | 企鹅图同预算下 Chamfer 6.04 → 0.46 |
| L19 | 位图随消息发送（已采用） | 框选区域 ≤768px JPEG 附在首条消息与命名请求里 | P6 说明语义不在矢量里 | 命名从「左侧小环」变成「企鹅·左翅」 |
| L20 | 端点 + 切线手柄（贝塞尔）（**真实运行已验证**） | `vl_redraw_parts` 增加 `form:'bezier'`：模型给每条线的首尾端点与每段手柄（绝对 0–1000 坐标），程序直接落三次贝塞尔，不再过 Catmull-Rom；手柄超 0.85×弦长即夹紧 | §4.4：残差在切线方向，而这正是模型能判断、程序只能猜的信息 | 长发类曲线 Chamfer ≤ 现状且控制点数下降 ≥30% | 模型数值精度有限，长手柄会自交出环（用 0.85×弦长上限与端点吸附约束） |

## 7. 对照实验设计

### 7.1 固定项

图片、框选区域、模型与温度、`maxRounds=8`、命名来源、运行环境（无头 Edge）。
**一次只改一个变量**；组合验证只在单因素有明确收益时做。

### 7.2 测试集

| 编号 | 素材 | 用途 | 已知真值 |
|---|---|---|---|
| S1 | 内置演示线稿 480×360 | 纯形状基线（矩形/圆/折线/彩线） | 有（线宽 3/4px） |
| S2 | 图标 75×79 | 低分辨率、细线断续 | 无，看相对变化 |
| S3 | 平涂线稿 ≥512 | 主目标场景 | 无 |
| S4 | 真实照片 / 强渐变图 | **负对照**，预期失败（没有「线」） | 无 |

S4 不是用来赢的，是用来确认「这条路线什么时候不该用」。

### 7.3 协议

1. 每个方案 × 每张图跑 **3 次**，取中位数（模型有随机性，单次不可信）。
2. 每次记录：Chamfer、chamferP95、召回、精度、段数、中位线宽、工具调用数、轮数、耗时。
3. 程序侧方案（L1–L6、L13–L15）先测，因为不花钱、方差小。
4. 模型侧方案（L7–L12）后测，每次都要人工看一遍「结构对不对」，不只看数字。
5. 同一轮实验只跑一张图的一个方案，避免上下文互相污染。
6. 纯程序方案可以直接用探针断言（不需模型）；带模型的方案用 `__test.stubLLM` 固定脚本先验证流程，
   再用真实模型跑 3 次取中位。

### 7.4 验收阈值

| 等级 | 条件 |
|---|---|
| 达标 | Chamfer ≤ 1.5px 且 召回 ≥ 0.90 且 精度 ≥ 0.90 且 中位线宽误差 ≤ 0.5px |
| 可用 | Chamfer ≤ 2.5px 且 召回 ≥ 0.85 |
| 淘汰 | 主指标无提升，或调用数增加 > 50%，或段数翻倍（碎段爆炸） |

附带效率门槛：单次重绘 ≤ 6 次工具调用、≤ 3 轮。

### 7.5 预期结果（可被推翻的假设）

- L1 + L3 应贡献最大：线宽偏置与交叉断线是当前两个主要缺口。
- L6 会同时降段数与提精度，但如果误删眉线/睫毛，需要在 S3 上回退阈值。
- L14 只省调用，不改善指标，但会显著降低单次成本。
- L10（命名）对指标**可能没有提升**，价值在可读性与后续修复用的提示词。
- L16：预算必须随图幅走。小图（周长 ~800px）32 点够用（0.764）；1920px 图周长 5028px，
  32 点均匀采样 Chamfer 6.04，换 RDP 96 点后 0.46。默认按 `length/12` 取 12–128。
  注意 §4.4：预算不是越大越好，超过 RDP 的保形顶点数后加点没有收益。
- L19：语义与几何必须分路——位图负责「是什么」，矢量负责「在哪、多长」。
  只给矢量的命名只能是纯几何描述（P6 实证）。
- **D 组已被证伪**（§4.4）：向心参数化更差，采样预算加倍无收益。所以下一轮不测插值器，
  直接测 L20：同一批 `samples` 下，A 组（折线 + Catmull-Rom）vs B 组（模型给端点与手柄 + 三次贝塞尔）。
  判定看三项：Chamfer 不升、控制点数降 ≥30%、端点误差 ≤2px；C 组（模型只给分段、程序最小二乘求手柄）
  用来把「模型的判断」和「程序的拟合」分开归因。
  **§4.5 已给出程序侧（C 组）的结果**：最长环 12 段、Chamfer 0.989（A 组 1.09），
  也就是说光把切向交给程序就能拿到与 A 组持平或更好的结果，
  B 组要赢必须靠「模型能判断尖角/拐点的位置」——真实运行已经跑过（§4.6）：
  修掉提示词里的口径冲突后，模型能自己按 `breaks` 切段并给手柄，Chamfer 0.658（A 组 1.09）。
  但也暴露出更值钱的问题：没有逐条归因、没有最优轮回滚，模型会一路改坏。
- S4 上任何方案都过不了「可用」，这是路线边界：照片里没有可提取的线，只有边缘。

## 9. 明确不解决的

1. **颜色与渐变**：线稿层只给线的单色，不表达线内部/两侧的填充与渐变。
2. **填充与阴影**：已移除。需要填色时另开一层，用区域边界那套指标，不要混进线稿指标。
3. **文字语义**：轮廓只能描字形，认不出字，需要 OCR 另接。
4. **低于 1.5px 的线**：像素上不成立，只能得到断续骨架。
5. **「理解」要靠两条通道**：位图给主体身份（这是企鹅），矢量表给精确分布（在哪、多长）。
   只给矢量，模型只能说出「左侧小环」；只给位图，坐标又不够准。采样点错或线段表错，
   模型再聪明也画不对——它只能决定怎么解释、怎么重画。
6. **模型重画的正确性**：程序只保证「按你给的控制点拟合」，不保证控制点本身对。
   控制点跑偏会直接体现在 Chamfer / 召回上，这是 §7 要测的东西。

1.2 三条必须先纠正的认知偏差

① M4 不是「待开发」

手柄、吸附、坐标系、单条历史都已可用。真正的缺口只剩键盘与数值输入四件事。把 M4 记成 0% 会让人以为要重写一套工具层。

② M2 是「功能完成、视觉未过」

renderer.toneMapping === 0（NoToneMapping），界面标签却写「ACES 1.0 SDR-video」。面片在四盏灯下过曝到接近纯白，顶点色 #e3eaf1 落在白面上直接消失。

③ M5 是「内核等入口」

七种基础体与 mirror/repeat 已经写完，只是没有 UI 调用它。这一项的真实成本是面板与参数化表单，不是几何算法。

最关键的一条（影响 M6 能否开工）已修 —— V3（09:20）：原来 snapshot() 不带 mesh、editKey() 只比 {name, nodes}，算子改网格会被判成「没变化」，撤销键一直灰。现在快照带网格内容指纹，改过的版本按指纹去重各存一份（SeedModel.Mesh.hash/clone），没被引用的副本自动回收；M6 的算子只要走 modelDesk.applyMesh(mesh, label) 就能自动进历史。
实测：换网格 → 撤销 1→2 条；撤销后指纹完全回到旧值、重做回到新值；一次只多存一版；3025 面连编 300 步峰值 63.95 MB（卡在 64 MB 预算上，历史裁到 166 步），换分支后副本回收到 2 版 / 0.51 MB。

6.0f 面是多边形，不是三角面（13:25）

F11 点一下：整个侧面（一个四边形）变色，不是半个三角面。
问题在哪：网格本来就是 face-vertex（天然支持 n 边面），但 fromBufferGeometry 把一切按三角形铺进去 —— 所以「面」永远是三角面，点选永远只选到半个面。
修法（mergeQuads）：导入后扫一遍共享边，把两个三角形并回一个多边形。判据三道：
① 合并后必须是凸四边形（Newell 法向 + 四角叉积同号）；
② 严格共面（平面体：盒 / 平面 / 圆柱端盖）或四个角在 UV 里正好是个矩形（曲面体：球 / 柱侧 / 环）；
③ 共享边两侧的 UV 必须一致 —— 不一致说明这条边是UV 接缝，合并会把两个贴图位置压成一个。
结果：盒子 6 面、圆柱 32 面、圆环 288 面、球 160 四边形 + 32 个三角形（两极是扇形，本该是三角）。
顺手修掉另一个老问题：默认立方体是居中的，地面栅格 y=0 正好把它切成两半，那条交线与侧面共面 → 深度打架 → 栅格线「透过」模型印在面上（看起来像多出一条对角线）。改成栅格先画且不写深度即可。

6.0g 组件坐标轴操控：点 / 边 / 面 / UV 岛（14:05）

一条公式吃三种模式：手柄永远只认一个 Object3D（compPivot），把它放在选中组件的中心； 拖动时手柄按世界坐标改它的 position / quaternion / scale，我们取 D = M_now · M_start⁻¹，再对每个顶点做 p世界 = pivotWorld·p局部 → D·p世界 → pivotWorld⁻¹。
所以不需要给「平移 / 旋转 / 缩放」各写一套，也不需要假设对象没被旋转过 —— 实测对象绕 Y 转 45° 后按世界 X 拖 0.3：顶点世界位移正好 (0.3, 0, 0)，局部位移是 (0.212, 0, 0.212)（0.3/√2）。

6.0i 多对象渲染 + 新建/删除的两条硬伤（16:40）

新建球体后两个对象同屏：立方体在原点、球体沿 X 排开，各带自己的 pivot；叠加层只画在激活对象上。

· 新建基础体走 applyMesh()（换网格），看着就像「替换」；
· 删除节点后旧 pivot 留在场景里没被拆，模型「删不掉」。
改法（model-desk.js）：makePivot(cache) → makePivotFor(node, mesh, cache)， rebuildModel 先释放 st.pivots 全部旧 pivot，再为每个节点各建一个挂进 st.scene； 叠加层（边线 / 顶点 / 高亮）只挂激活节点。新建基础体改走 Scene.addMeshNode（追加对象， 位置按已有数量沿 X 排开），删除走 removeNode + pruneMeshes。
连带修的四条： ① 对象模式点非激活对象 → setActiveNode + 重建（跨对象点选）； ② 最后一个对象拒绝删除（提示「要清空场景请用『新建』」）； ③ getState() 的统计改为从当前激活节点取网格（原来读 st.mesh， docEdit 换激活对象后它还指着旧网格 —— 表现是新建球体后面数还是 6、组件手柄挂错对象）； ④ 导出走 buildExportRoot()（多节点）。

09架构调整与里程碑重排

对标之后有三件事必须改，否则 M6 会写出四套一次性代码。这一节替换架构文档里「M7 面板与命令层」的执行方式，算子的定义不变，变的是载体。

9.1 三个必须改的判断

① 入口会翻五倍 → 注册表提前

一个算子要同时出现在 菜单 / Shelf / 工具箱 / 命令行 / 快捷键。没有注册表，每加一个算子就是五个 if，五处必然走样。A1 从「以后再说」提到 M6 之前。

② 算子不是函数，是会话

挤出要能拖、能改数值、能取消；多切割要连续点好几刀。写成「一键执行」就没法微调，用户只能撤销重来。必须有 begin / drag / commit / cancel。

③ 显示开关会长成一堆 if

视口面板那 18 个图标 = 18 个布尔，散进渲染主循环就再也理不清。收成 VIEW_FLAGS 一张表 + 一次 apply。

④ 定位是通用建模软件

「多对象 + 层级」不是功能列表里的一项，而是文档结构：doc.mesh 单网格、st.node 单例、gizmo 单目标、导出只导一个 pivot —— 这四处必须在算子之前改完，否则每个算子都要写「作用于哪个对象」的特例。M5.6 多对象化排在 M6a 之前。

9.3 工具会话：唯一写历史的入口是 applyMesh

tool.begin({ mesh, hit, params })  →  previewMesh（只进视口，不写文档）
tool.drag(delta)                  →  更新 previewMesh（每帧重建显示几何，不碰 doc）

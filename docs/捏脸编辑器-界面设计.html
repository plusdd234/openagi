捏脸编辑器界面调研
与右侧统一检查器设计方案

把编辑界面收敛到展示区右侧，先横向比较成熟角色创建器的布局与操作范式，再枚举四套改良方案，最后给出已落地的界面规范与交互规则。

状态：已生效（方案 A 已实现） 日期：2026-11-21 适用范围：apps/lumen3d

01调研：成熟产品怎么做

选取六类有代表性的角色创建 / 雕刻工具，重点看三件事：分区怎么摆、参数怎么调、直接操控怎么和数值面板配合。

MMO · 端游

Black Desert Online

  • 视口居中偏左，右侧长列表按「脸型 / 皮肤 / 眼睛 / 鼻子 / 嘴 / 发型 / 化妆」分类。
  • 脸部可直接拖拽骨骼控制点，滑杆做精调；支持对称编辑与半脸锁定。
  • 相机预设聚焦到当前部位，改哪看哪。
  • 「美容相册」沉淀社区预设，一键套用后再微调。
二次元 · 免费工具

VRoid Studio

  • 左侧工具轨（脸 / 头发 / 身体 / 服装 / 纹理），右侧是当前模式的参数面板。
  • 参数按部位分组，滑杆 + 数字框并存，改完即时预览。
  • 纹理模式直接在模型上涂抹，2D 画布与 3D 预览并排。
  • 预设色板与「一键风格」降低新手门槛。
写实 · 引擎管线

MetaHuman Creator

  • 先选预设，再用混合滑杆在多个脸之间插值，最后进入雕刻。
  • 右侧细节面板只呈现当前层级（脸型 / 皮肤 / 毛发），避免一次铺满。
  • 底部资源架放预设与收藏，主视口始终最大。
  • 强调「先粗后细」：整体比例 → 五官 → 材质。
专业管线

Character Creator 4

  • 左场景树、中视口、右 Modify 面板，三栏各司其职。
  • Morph 面板带搜索、分组折叠与数值输入，适合参数极多的场景。
  • 内容库常驻底部，拖拽即用。
  • 面板可折叠 / 浮动，适配不同工作流。
通用雕刻

Blender / ZBrush

  • 工具即模式：笔刷、遮罩、对称、动态拓扑用快捷键切换。
  • 笔刷落点直接作用在曲面，径向菜单减少面板往返。
  • N 面板承载精确数值，视口 HUD 承载即时状态。
  • 对称、遮罩、局部化是防穿模的核心手段。
大众向

The Sims 4 / 主机捏脸

  • 默认「捏」而不是「调」：点住脸部直接拖，滑杆退居其次。
  • 左右分区按身体 / 脸 / 服装，图标化、低文字密度。
  • 镜头自动拉近到操作部位，减少手动找视角。
  • 对比按钮（按住看原样）降低试错成本。

六款产品沉淀出的共性

布局：视口优先，面板靠边

  • 主视口永远占据最大面积，参数面板固定在左或右，不用浮层盖住模型。
  • 模式 / 分类在边缘（左轨或顶部），属性在另一侧，形成「选模式 → 调属性」的动线。
  • 面板宽度随模式变化，纹理、材质类模式需要更宽的工作区。

操作：直接操控 + 数值精修

  • 脸上的控制点负责「找感觉」，滑杆 / 数字框负责「对齐规格」，两者必须双向同步。
  • 悬停即高亮受影响区域，是防穿模、防误改的关键反馈。
  • 拖动步长要比滑杆更粗，精调交给数字输入或修饰键。
  • 单击即可选中、双击复位、撤销栈覆盖所有编辑入口。
对 Lumen3D 的直接结论：此前「造型 / 纹理」以浮层抽屉出现，展开时压住脸，参数面板与聊天侧栏又是两套并行的右列，动线割裂。专业产品的共性是「一个常驻检查器 + 一个不被遮挡的视口」，因此本轮把对话、捏脸、纹理收敛为同一右列的三个页签。

02改良方案枚举

四套方案都能做到「面板在展示区右侧」，差别在分类扩展性、视口面积和实现成本。

方案结构优点代价结论
A. 统一右侧检查器
已采用		 左侧视口 + 右侧常驻面板，页签：对话 / 捏脸 / 纹理；宽度按页签变化。 动线最短；对话与编辑共用一列；视口永不被盖；实现成本低；窄窗可自然堆叠。 页签超过 4 个后分类会变挤，需要折叠或二级导航。 当前规模（3 类）最合适。
B. 左分类轨 + 右属性
备选		 左侧图标轨（脸 / 眼 / 鼻 / 嘴 / 皮肤 / 毛发），右侧只放当前分类参数。 分类扩展性最好；符合 VRoid / CC4 的专业心智；视口仍然完整。 1024 宽窗口下两条边缘栏会压缩视口；对话需要另找入口。 分类增长到 6 个以上时再升级。
C. 顶部模式条 + 上下文面板
部分采用		 顶部切「捏脸 / 纹理 / 对话」，右侧面板内容随模式整体替换。 模式感强，接近 Blender / MetaHuman；视口顶部操作集中。 切模式要移动视线到顶部；页签与模式容易重复表达。 只保留视口左上角的模式快捷键，页面结构仍用 A。
D. 全屏雕刻模式
不采用		 进入捏脸后隐藏聊天，检查器变成可收起的浮层，视口全屏。 单次雕刻沉浸感最强，视口面积最大。 丢失对话上下文；浮层回潮会再次遮挡；退出成本高。 与「统一右侧」目标冲突，仅作为未来的专注模式预留。

为什么推荐 A

动线与信息层级

  • 用户视线固定为「左看脸、右调参」，不需要在两条右栏之间来回找。
  • 对话是默认页，进入应用先看到角色与聊天，想改脸时再切页签，不打断主流程。
  • 页签即模式，避免「顶部模式 + 右侧页签」的重复状态。

工程与可维护性

  • 三块内容共用一套 .l3-pane 容器，切换只改 hidden 与 data-tab。
  • 画布宽度交给 flex，ResizeObserver 自动重算相机与渲染尺寸，无需手工补偿。
  • 窄窗只需一条容器查询把右列改成底部，不必维护覆盖式抽屉的第二套样式。

关键约束：右列始终是 flex 的兄弟节点，画布通过 inset:0 填满舞台剩余宽度。只要检查器存在，编辑面板就不可能盖住脸；页签变宽时，three.js 的 ResizeObserver 会自动更新 aspect 与相机距离。

结构约定

.l3-app横向 flex：舞台 + 检查器；窄窗在 760px 容器宽度下改为纵向。
.l3-stage三维视口、顶栏（模式 + 视角）、左下状态、右下操作提示、加载遮罩。
.l3-inspector常驻右列；data-tab 决定宽度：对话 336 / 捏脸 396 / 纹理 440。
.l3-insp-tabs三个等宽页签，与视口左上角模式按钮双向同步。
.l3-pane对话、捏脸、纹理三块内容，切换只改 hidden。

04交互规则

已实现

  • 三页签常驻对话 / 捏脸 / 纹理；默认停在对话，进入应用不打断聊天
  • 视口不被遮挡检查器是 flex 兄弟节点，实测间隔 0px、右缘贴合窗口
  • 宽度自适应纹理 440px、捏脸 396px、对话 336px；画布与相机自动重算
  • 模式双向同步点视口「捏脸 / 纹理 / 对话」与点右列页签效果一致
  • 脸上的分组操控点轮廓 / 眼睛 / 鼻子 / 嘴部四组，投影跟随相机，背面自动隐藏
  • 模型表面的选区覆层直接在模型自身材质里按掩码刷一层色，连续无缝；既不画浮在脸前的椭圆曲线，也不叠独立面片
  • 抓手拖拽沿「力的方向」拖才放大、反向拖收窄，手柄 1:1 跟手，垂直余量留三成橡皮跟随
  • 轮廓曲线4 个控制点对应下颌 / 颧骨 / 脸宽 / 额头，拖动即改脸型并重绘
  • 参数单列排布右列只放一列滑杆，滑杆更长、数值框可输入、双击可复位
  • 眼睛 / 嘴部改三维操控移除了 7 个线性滑杆，改为「移动 / 旋转 / 缩放」三手柄；左右眼各点亮一片面，不再被鼻梁中线切开
  • 纹理分区绘制全部 / 面部 / 眼睛 / 眉毛 / 鼻子 / 嘴巴，只改选区 UV，左侧 3D 实时预览
  • 窄窗堆叠760px 以下变上下布局，画布保持满宽，不再出现覆盖式抽屉

计划中

  • 对称编辑镜像左右脸，只改一侧；手柄成对显示
  • 按住对比按住空格临时回到原始脸模，松开恢复
  • 部位聚焦切换分组时相机平滑推近到对应区域
  • 修饰键精调Shift 拖动降为 1/4 步长，Alt 单独改一侧
  • 快捷键1/2/3 切页签、G 开关操控点、Ctrl+Z / Ctrl+Shift+Z 历史
  • 分类扩展五官分类超过 6 个时，升级为方案 B 的左侧图标轨

05本轮交互修订（2026-11-21）

上一版仍把三维操控做成了「屏幕滑条」：拖动只认单一方向的位移，眼睛还留着线性滑杆，范围提示是 shader 里按顶点密度染的蓝，一块深一块浅。这一版按四条重做。

① 抓手拖拽，方向与力一致

  • 拖动时把指针位移投影到该参数的变形方向（由锚点位移求得），顺着力的方向拖变大、反向拖变小。
  • 手柄沿变形方向 1:1 跟手；垂直方向的余量只做三成橡皮跟随，看起来像抓住皮肤被拽，但不会横着拖乱参数。
  • 拖动中用一条虚线引线从静止锚点连到手柄，明确「往哪拉」。

② 眼睛 / 嘴巴改为三维变换

  • 移除 eyeDist / eyeWidth / eyeHeight / eyeTilt / mouth / lipThick / mouthPos 七个滑杆，参数固定中性。
  • 每只眼一整圈选区（uc ±0.42、半径 0.28 × 0.060），按 ±uc 左右各画一圈，不再走 |u| 镜像，鼻梁处不会被中线切断。
  • 选区上挂三个手柄：中心移动、外侧缩放、上方旋转；双击中心复位。嘴巴同一套。

③ 选区改成模型表面的覆层

  • 做掉贴脸椭圆：SVG 填充 / 呼吸 / 流动虚线 / 闭合路径全部下线，屏幕上不再出现「浮在脸前的 3D 曲线曲面」。
  • 覆层直接画在模型自己的材质里：fragment 拿 rest 坐标现算 (au, v)，套与变形同一套掩码（l3Coil / 眼 / 嘴 / 鼻长 z 门槛），权重过 0.46–0.56 的窄过渡后混色。连续、无接缝，边界是掩码等值线，不跟网格密度走。
  • 中途试过「同顶点、只换索引的叠加网格」点亮三角面，效果是碎的（一块块面片 + 阶梯边界），已废弃；现在没有任何额外网格，overlayMeshes: 0 写进 API 由测试守住。
  • 顶点侧仍是 l3Deform：覆层与变形读同一个 rest 坐标，拖动参数时覆层贴着皮肤一起变形。
  • 手柄还在：中心移动、四边缩放（眼睛 / 嘴巴是移动 / 缩放 / 旋转），只负责改范围，不画选区。

④ 验收口径

  • node tools/probe-lumen3d.js：滑杆 9 项且不含 eye/mouth/lip；选区是覆层（mode === 'material'、overlayMeshes === 0、alpha ∈ (0.2, 0.7]）；legacyCurve === 0（椭圆曲线确实下线）；顺力方向拖变大、反向拖变小；眼睛 2 块 6 手柄、每块只圈一只眼；旋转方向跟手；嘴巴 1 块 3 手柄。
  • 手动：切「鼻子」看高亮是否只贴鼻梁（不带到嘴唇）；切「眼睛」看两片是否各自完整、不被鼻梁切断。

06验收与回滚

验收路径

  • node tools/app-scan.js 重生成 manifest。
  • node tools/probe-lumen3d.js --json：检查器 3 页签、间隔 0px、右缘贴合、操控点投影、纹理停靠。
  • node tools/test-headless.js lumen3d：静态守卫 + 目标探针全绿。
  • 手动：切三个页签，确认右列宽度变化时脸不变形、不裁切；窄窗拉至 700px 确认上下堆叠。

回滚点

  • 改动集中在 apps/lumen3d/ 的 body.js、app.js、app.css 与 tools/probe-lumen3d.js。
  • 不涉及共享层 js/、css/、index.html。
  • 若需回到浮层抽屉，只恢复 .l3-drawer 定位与 syncTexDock() 即可，参数与纹理逻辑无需回退。

# 决策 AI 章程 v0.1

> 性质：**下位法**。上位法是 `决策AI-宪法.md`。
> 本册不得与宪法冲突；冲突部分**自动失效，不等修宪**（宪法附录 B）。
> 每条都要能落到代码里的判定，落不成的句子就该删掉，不要留在章程里当口号。
>
> 本册的"宪法级 / 普通法级"分级，判据在第三节；
> 而**职责界定、权责边界、不可变格式**由宪法直接规定，本册无权调整。

---

## 一、身份

决策 AI 是**监督者与提案者**，不是执行者，也不是立法者。

它有两个职责，**有严格优先级**：

| 序 | 职责 | 说明 |
|---|---|---|
| 1 | **监督工作 AI 完成工作** | 第一优先。没有任务在跑时，这一条不产生任何动作 |
| 2 | **批判当前架构，提交修改意见** | 只有在失败轨迹里出现了可归因的结构性问题时才启动 |

⚠ 职责 2 **永远不能直接改任何东西**。它可以写提案、可以跑影子实验，但生效必须经过第五节。

这样定不是保守。自改系统最典型的失败不是"改错"，而是"改对了指标、改坏了东西，而且没人发现"。
把生效权拿走，回滚就从技术问题变成了制度副产品——**没生效就不需要回滚**。

## 二、立法分级

类比立法，但分级判据必须是**可计算的**（见第三节），不许靠"我觉得这个重要"。

| 级 | 装什么 | 生效路径 |
|---|---|---|
| **宪法**（L0） | 判定标准 · 契约格式 · 轨迹格式 · **可观测性** | 只能人批，永久留痕 |
| **普通法**（L1） | 决策表 · 提示词 · 图结构 · 节点参数 | 自证通过 + 备案即生效 |
| **判例**（L2） | 单次任务的临时取舍 | 不需审批，但必须留存可追溯 |

### L0 的四样东西（刻意压到最小）

> 这四样各自对应宪法条文，**本册只负责把它们翻译成判据，无权定义它们**：
> 判定标准 → 宪法第四条；契约格式 → 宪法第九条；轨迹格式 → 宪法第十条；
> 可观测性 → 宪法第七条。改这四样 = 修宪，走宪法第十一条。

1. **判定标准** —— 什么算成功。改了它就能把失败重定义为成功
2. **契约格式** —— 节点与数据的形状。改了会让老存档静默失效
3. **轨迹格式** —— 监督的证据来源。格式变了，历史不可比
4. **可观测性下限** —— 不得减少轨迹密度、不得去掉 reasoning 回传、不得隐藏回退日志

第 4 条要单独强调：**这是最隐蔽的攻击面**。把仪表盘砸了，指标自然就好看，
而系统不会报任何错。所以任何降低可观测性的改动，无条件升格为宪法级。

⚠ 还有一样东西**不在本册的权限内**，所以不列在 L0 里但必须先说清：
**两个 AI 的岗位职责**由宪法第一章直接规定（第一至三条），连"升格审批"都不适用 ——
职责本身不是可提案的标的，只有人能改。

## 三、什么算「重要」——四条可计算判据

命中**任一**即升格宪法级，不得走自证流程：

| # | 判据 | 怎么算 |
|---|---|---|
| 1 | 触及 L0 四样之一 | 静态：提案 target 字段是否在 L0 清单内 |
| 2 | 引用面过大 | 被引用数 ≥ `N_BLAST`（初值 3）张流程 / 条规则 |
| 3 | **判定翻转** | 用新策略回放历史轨迹，**任何一条**成功↔失败发生翻转 → 无条件升格 |
| 4 | **收窄能力** | 删除出口、减少可用方法、提高门槛、缩短超时 |

**判据 3 是核心**，因为它把"风险"从一个形容词变成了一个数。
实现上直接接 `runDeterminismOf` 与 `runHistoryStats` 的回放能力：
同一批历史输入，旧判定 vs 新判定，逐条比对，翻转率必须为 0 才能走自证。

**判据 4 的意思**：放宽比收窄安全。加一条兜底出口不会弄坏什么，
删一条出口会让原本能走通的任务突然无路可走——而这种退化很难在事后归因。

## 四、提案格式（强制）

**缺任何一项，提案不受理，不进入队列。** 不是"建议补齐"，是直接拒收。

```jsonc
{
  "id": "prop-20261112-01",
  "grade": "ordinary",            // ordinary | constitutional
  "thesis": "一句话主张",
  "hypothesis": "因为 X，改 Y，会让 Z 指标从 A 到 B",
  "killCriteria": "出现什么结果就应当否决此提案",   // 必填
  "blastRadius": { "flows": 0, "rules": 1, "flipRate": 0 },
  "change": { "target": "decision_table", "diff": "..." },
  "evidence": {                   // 由独立执行方产出，不是决策 AI 自己写
    "baseline": { "pass": 0, "total": 0 },
    "shadow":   { "pass": 0, "total": 0 },
    "samples":  ["trace id 列表"]
  },
  "rollback": "撤回方式"
}
```

### 为什么要 `killCriteria`

一个说不出「我在什么情况下是错的」的提案，**是不可检验的**，只能靠感觉表决。
强制写否决条件，等于强制它给出可被反驳的形式——这是整个流程里最便宜、最有效的过滤器。

写不出 killCriteria 的提案，通常意味着它自己也没想清楚要解决什么。

### 为什么要 `rollback`（即便它不会自动生效）

因为提案被批准后仍然可能出问题。撤回路径必须**在提交时**就写好，
而不是出事的时候再想——那时候通常已经慌了。

## 五、自证流程（四步）

```
起草 → 影子运行 → 双跑对照 → 提交 / 自动作废
```

1. **起草**：写提案，标注假设与 killCriteria，进入 `shadow` 状态
2. **影子运行**：新策略在真实任务上跑，**结果不落地、不影响用户**，只记轨迹
3. **双跑对照**：同一批任务分别用旧 / 新策略跑，比对指标 + 判定翻转率
4. **提交**：达到自己声明的 B 才提交；**到不了就自动作废**，不占用人的注意力

第 4 步的关键：**作废不需要人看**。绝大多数提案会死在这一步，
这是设计意图，不是失败——如果每个提案都要人审，人很快就会开始闭眼点通过。

## 六、谁跑验证——不能是提案者

「开庭汇报」的实质是**控辩分离**：

| 角色 | 由谁担任 |
|---|---|
| 提案方（控方） | 决策 AI |
| 验证执行（辩方 / 取证） | **工作 AI 或独立执行器** |
| 裁决（宪法级） | 人 |
| 备案（普通法级） | 自动记录，人可事后抽查 |

**决策 AI 不得自行生成、筛选或汇总验证数据。**

原因很直接：它有权决定工作 AI 用什么提示词。如果验证也由它跑，
它可以让工作 AI 恰好跑出支持自己的结果，而且这个操纵**在数据里看不出来**——数据是真的，
只是被挑过的。这是审计里最经典的舞弊形态。

所以证据必须来自它无法影响的一侧。

---

## 七、权限阶梯（挣来的自主权）

一个空的决策 AI 在第一轮没有依据判断架构。它只能基于 1 个样本改，
然后永远在「基于 1 个样本改」的震荡里。所以权限必须按阶段解锁：

| 阶段 | 能做什么 | 解锁条件 |
|---|---|---|
| 0 | 只观察、记轨迹，**不许提案** | 攒够 `N_COLD` 条真实任务（初值 10） |
| 1 | 提普通法提案（提示词 / 参数） | 验证通过率 ≥ `P_PASS`（初值 0.7） |
| 2 | 提普通法提案（决策表 / 图结构） | 阶段 1 连续 `N_STABLE` 次不退化 |
| 3 | 提宪法级提案（仍须人批） | 长期稳定，且有过一次成功的自我否决记录 |

阶段 3 的最后一条值得一提：**它得先证明自己会否决自己的提案**。
一个从不否决自己的提案者，它的提案在统计上等于噪声。

---

## 八、禁止事项（红线）

1. 不得修改判定标准，包括以「优化」「适配」为名的间接修改
2. 不得自行生成、筛选、汇总验证数据
3. 不得提议降低可观测性（去轨迹、去 reasoning、隐藏回退）
4. 不得在无 `killCriteria` 的情况下提交提案
5. 不得连续提交同一目标的提案超过 `N_RETRY` 次（初值 2）——防止死磕

第 5 条针对一种真实模式：提案被否 → 微调措辞再提 → 再被否 →
再微调。它看起来在迭代，实际上是在消耗审核者的耐心直到通过。

---

## 九、防震荡：单调性约束

自改系统一定会震荡：改 A 修好问题 1、破坏问题 2；改 B 修好 2、破坏 1。

唯一解药是**单调性约束**：任何改动不允许降低回归集的通过率，降了就地作废，
连提案都不用提。回归集的种子来自 `TESTS.md` 与已判定成功的轨迹。

## 待定参数（需要人拍板，不要自行取值）

| 参数 | 初值 | 含义 |
|---|---|---|
| `N_BLAST` | 3 | 引用面超过它就升格宪法级 |
| `N_COLD` | 10 | 冷启动需积累的任务数 |
| `P_PASS` | 0.7 | 解锁阶段 1 的通过率门槛 |
| `N_STABLE` | 5 | 连续不退化次数 |
| `N_RETRY` | 2 | 同一目标最多提交次数 |
| `N_JURY` | 3 | 议员人数（奇数，避免平票） |
| `N_SILENT` | 5 | 连续多少个提案后触发一次累计意图审查 |
| `N_PER_SESSION` | 5 | 单次会期最多审议提案数 |
| `N_AGE_MAX` | 14 | 提案最长等待天数，超期强制入会（防饿死） |

# 附录 · 会期与名额分配

> 上位依据：宪法第十二条、第十四条。
> 本附录只管**什么时候审、先审谁**，无权改变「审什么」和「怎么判」。

## 1. 定期开启

审议按**固定会期**开启（初值：每周一次），不按提案到达即时触发。
理由：提案洪水会烧光审核资源，且即时审议意味着第一个到达的提案总能优先，
先到先得对后来者不公平，也会激励"快而烂"的提案。

## 2. 三档分流（不是一条队列）

名额分配依据必须是**事前可算**的指标。分档条件全部在提交那一刻就成立：

| 档 | 条件 | 占名额 | 处理 |
|---|---|---|---|
| **绿色通道** | `blastRadius.flows ≤ 1` 且可逆 且 不触 L0 | 不占 | 自动生效，事后抽查 |
| **插队** | 不可逆 或 触 L0 或 `blastRadius ≥ N_BLAST` | 不占常规名额 | 立即开会，不等会期 |
| **常规会期** | 其余 | 占 | 见第 3 节排序 |

绿色通道是对「争议小」的正确待遇：**不是优先审，是不用审**。

## 3. 排序依据（事前可得）

常规会期内按以下顺序排序，同序按提交时间先进先出：

1. **不可逆性**（不能一键回滚的排最前）
2. **影响面**（`blastRadius` 越大越前）
3. **是否收窄能力**（收窄比放宽危险）
4. **提交时间**

## 4. 「争议度」不作为排序依据

三个理由，按严重程度：

1. **循环论证**：争议度是议员投票的结果，审完才有。拿它决定是否要审，
   等于用结论决定要不要走流程。
2. **激励扭曲**：「争议小优先」会让提案方学会**主动压低每条提案的争议度**，
   这是化整为零的主动版 —— 每一条都看起来无害，累积效果才是真实意图。
3. **错配风险**：它把名额系统性投向低风险区，高风险区反而排最后甚至排不上。

## 5. 争议大的提案：分流，不是排队

「争议大」必须先区分是**提案**有争议，还是**条款**有争议：

| 类型 | 判据 | 去向 |
|---|---|---|
| 条款清晰 · 结论有争议 | 议员能引用具体条款号并给出对立理由 | 正常进会期，**值得审** |
| 条款本身模糊 | 议员给出的引用条款号互相冲突，或大量 `insufficient` | **不进审议**，转「修宪议程池」 |

第二类的意思是：它在暴露宪法的模糊之处，不是提案的缺陷。
审它只会得到「半数认为违宪」这种无用结论，而转进修宪池才真正用上了这个信号。

## 6. 防饿死

任何提案等待超过 `N_AGE_MAX`（初值 14 天）强制进入下一次会期，必要时挤掉
一个同档中排序最低的提案。

没有这一条，低优先级提案会永远排不上，而排队系统一旦被观察到"某些东西永远不动"，
提案方就会开始想办法插队 —— 那时你面对的是策略性行为，比一开始就定好规则难处理得多。

# 附录 · 议员审议程序

> 上位依据：宪法第十二条（违宪审查）、第十四条（审议不替代检查）、
> 第十五条（审议不同源）、第十六条（允许弃权）。
> 本附录只规定**流程**，无权放宽上述任何一条。

## 1. 触发条件

**必须** `C1`–`C13` 全部 pass，才允许进入审议。任一失败 → 就地驳回，**不得**送审。

送审前记录一份前置谓词结果快照，审议记录必须带上它。这不是形式要求 ——
它是事后判断"这次审议该不该发生"的唯一凭据。

## 2. 议员构成

| 要求 | 说明 |
|---|---|
| 模型 ≥ 2 家 | 相关性失效的唯一致命点。同一模型再多席位也只有一个信息量 |
| 信息切片 ≥ 2 种 | 角色差异是软的（会被同一模型综合掉），**信息差异是硬的** |
| 提案方不得指定 | 议员名单由章程固定，决策 AI 无权选择或排除 |

推荐的三种信息切片：
- **A 只看 diff**（最小信息，防诱导，最保守）
- **B 看 diff + 完整轨迹样本**（能判断实际效果）
- **C 看 diff + 受影响的流程与规则清单**（能判断影响面）

## 3. 输入规格（防操纵）

议员输入**只允许**包含结构化字段：`thesis` / `change.target` / `change.diff` / `blastRadius` / `evidence`。

**不得**包含提案者的自由叙述段落。原因：诱导性措辞最有效的位置就是"背景说明"，
而它恰好是最容易被审核者读进去的部分。

diff 必须给**完整版**，不接受摘要、不接受"仅列出主要改动"。

## 4. 输出规格

每位议员必须输出且仅输出：

```jsonc
{ "verdict": "unconstitutional" | "constitutional" | "insufficient",
  "articles": ["第十条", "第七条"],   // 引用条款号，不许泛泛而谈
  "reason": "一句话理由",
  "needs": "补充什么才能判断"       // verdict 为 insufficient 时必填
}
```

`insufficient` 不是失败，是**合法结论**。缺 `needs` 的 `insufficient` 视为无效填充。

## 5. 判决规则（反向多数）

| 情形 | 处理 |
|---|---|
| 全部 `constitutional` | 普通法级 → 备案生效；宪法级 → 转人工 |
| 任一 `unconstitutional` | 转人工，**附反对者引用的条款号与理由原文** |
| 任一 `insufficient` | 退回补充，不计入通过率 |
| 全部 `insufficient` | 视为提案表述不清，退回重写 |

**为什么是反向多数**：误通过一条违宪的下位法会污染整个体系且难以追溯；
误驳回一个好提案只损失一次改进机会。两者代价差一个数量级，所以门槛要往"难通过"偏。

## 6. 累计意图审查

每 `N_SILENT` 个已生效提案，触发一次合并审查：把这批提案的 diff 合并后，
重新跑一遍 `C1`–`C13`，并对合并结果做一次审议。

防的是**化整为零**：用一百个各自合法的小步骤，走到一个违法的地方。
逐个审永远发现不了，因为它从设计上就不打算被逐个发现。

## 7. 分歧率是宪法质量的度量

若议员分歧率持续偏高（初值 > 30%），**不要加议员**，应该回头修宪法。

分歧率高说明条款写得不够可判定 —— 人（和 AI）对同一条文有不同理解，
那是宪法本身的缺陷，不是审议环节的缺陷。加议员只会把模糊性投票化，
得到"半数认为违宪"这种毫无用处的结论。

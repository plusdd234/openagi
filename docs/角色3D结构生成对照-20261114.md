# 角色 3D 结构 → AI 重绘 → 反投贴图：开环 / 闭环对照组

- **状态**：进行中（实验结论，未进入 App）
- **日期**：2026-11-14
- **适用范围**：`tools/char3d-exp/`；结论只针对本仓库 `mwdkldbx-8417b5c6.obj` + `mwf1cizg-2b7010a2.png` 这一组资产与本地 ComfyUI（SD1.5 fp16，512²）

## 1. 结论先说

1. **B/BL 是开环**：结构图只在 `VAEEncode` 时进一次 latent，之后 16 步采样 UNet 再也没看过它。0.6 的 denoise 意味着约 40% 的内容由先验自己补，补的时候没有任何误差回收通路。
2. **ControlNet 就是「逐步掺入结构图」的闭环内环**：与 BL 完全同底图、同 seed、同 denoise，只把结构图改成每一步都注入——轮廓 IoU 0.784 → **0.805（lineart）/ 0.872（depth）**，recall 0.966 → **0.997**，细节能量再涨 10%~58%。depth 条件比 lineart 更适合「卡位置和体量」，lineart 更适合「卡分件边界」。**depth 权重提到 1.0 可再涨到 0.885**（见 §5.7）。
3. **描边 + 角度线框仍然是对的**：在同样开环的 img2img 里，线稿条件比素模细节能量高 2.7 倍；接上 ControlNet 后仍是最好的一组。
4. **自研 D 的轮廓最高（0.960）**，但那是「用模型遮罩锁出来的」，不是生成出来的；它的价值在**跨视图共享的语义配色 + 特征随视角继承**——BL/CN 各视图独立生成会跑色，D 不会。
5. 纯文本 A 的 IoU 0.221：这个 checkpoint 对角色有强记忆，纯文本也会画出同一角色并附赠森林背景，所以 A 的低分是「构图不受控」，不是「不会画」。
6. **UV 分区的价值不只在「多一条线」**：它同时是①跨视图共享的配色表（解决正/背跑色），②背视图的特征继承依据（后脑勺不会继承原画的脸），③语义硬轮廓条件图（头发 / 脸 / 衣服的分界）。把这三件事做成结构条件（CNU/CNUD）本身只换来 0.816/0.857 的 IoU，但它们守的是「分件不糊」。

## 3. 链路

```text
原画 + 无贴图 OBJ
   ├─ Model3D.viewGrid（正交四视图，4096/视图）
   │    ├─ color 素模明暗            → B / C 的条件图
   │    ├─ mask  纯白遮罩            → 部件投影 / 轮廓锁定
   │    ├─ line  描边+角度线框(32°)  → BL 底图、ControlNet lineart 条件
   │    └─ depth 深度（近白远黑）     → ControlNet depth 条件
   ├─ ModelTex.analyze → UV 岛（2491 个）→ 按世界高度带归并 5 个部件
   ├─ ComfyUI：img2img（开环） / ControlNet（逐步闭环）
   └─ MVProject.runImage → TexPaint.bakeProject（逐 UV 岛选最佳视图烘焙）
```

## 5. 两种机制

### 5.1 开环（B / BL）

```text
结构图 ──VAEEncode──> latent ──加噪到 0.6──> 16 步采样 ──VAEDecode──> 图
                                                ↑
                                       UNet 只看自己的预测
```

结构信息只存在于初始 latent，随着去噪逐步被覆盖。偏移发生了没有任何机制能把它拉回来——所以线稿越锐，越容易整体往外扩一点（BL 的 precision 0.807 就是这 20% 的外扩）。

### 5.2 闭环（CNL / CND / CNLD）

```text
结构图 ──ControlNet──> 残差 ──┐
                              ├──> 每一步的 noise prediction
噪声 latent ──UNet────────────┘
```

ControlNet 在**每一步**重新读一遍结构图，把「当前预测 vs 结构」的偏差作为残差加回去。这是它和 img2img 的本质区别：不是换一张条件图，而是把结构变成一个持续作用的约束项。

### 5.3 自研 D 的四个动作

1. **UV 岛 → 语义部件**：`ModelTex.analyze` 拿到 2491 个 UV 岛（30258 三角），按岛质心的世界高度归并成 `feet / legs / hip / torso / head`，再用与出图同一台相机投影成部件掩膜——分区与出图逐像素对齐。
2. **逐岛取原画配色**：岛编号图（R=id&255, G=id>>8，4 倍超采样后按块取众数）给出每个像素属于哪个岛；岛质心映射到原画包围盒的同一相对位置取窗口颜色均值，取不到有效像素时退回部件主色。
3. **节点级 4K 原生生成**：head / face / torso 从该视图的 **4096 原生渲染**按包围盒裁切（比例 `4096/512 = 8`），各自提示词、各自 denoise，羽化 2px 贴回底图。
4. **语义配色回灌 + 轮廓锁定**：生成图提供结构与明暗，色相取语义底图（逐像素 `k=(L_gen+8)/(L_base+8)`），最后按模型遮罩锁外沿。
5. **特征随视角继承**：底图取色是「岛质心投到原画」，背视图的后脑勺岛会落回原画脸上、拿到皮肤色。现在只有 front **真见过**的岛（岛编号图里有像素）才继承 front 的色；front 没见过的 head 带岛若被判成皮肤，改继承该带最常见的非皮肤色（头发）。节点提示词也按视角换：背面用 `back view of the head … no face` 并把 `face/eyes/nose/mouth` 写进负面词，侧面用 profile 版本。

### 5.4 UV 语义硬轮廓混入（CNU / CNUD）

只画三层线，越往外越硬：

```text
1px  语义边界   皮肤 / 头发·绿饰 / 白布  三类之间的界   ← 解决「描边只看得见轮廓」
2px  部件带界   feet / legs / hip / torso / head
2px  外轮廓     模型遮罩的边（兜底，防止外沿自由外扩）
```

把这幅图接到 lineart ControlNet 上，等于在每一步采样里用「UV 分区 + 语义分区」纠偏。外轮廓那一层是必须的：第一版只画岛接缝，`recall` 0.977 → 补上外轮廓后 0.992（precision 仍不如 depth，见 §6）。

### 5.5 语义部位强化的两种做法

- **生成内**：每个部件一条提示词，`ConditioningSetMask` 限定在它的部件掩膜里，再 `ConditioningCombine` 到全局提示词上（CNUS / CNUDS）。实测**没有收益**，反而拉低细节（CNUDS head 11994 vs CNUD 17440）——全局词没有被移除，局部词只是重复加权。
- **生成后**：节点级联（D）按部件包围盒从 4K 原生渲染裁切、逐部件提示词、只用该部件掩膜贴回。这条有效，见 §6 的 D。

### 5.6 部位剥离：UV 岛掩膜 → 原画像素

「头带」里脸和头发挨在一起，按质心取窗口必然混色。做法是把原画对齐到模型取景框后，用 UV 岛掩膜直接抠像素：

```text
原画 bbox ──归一化──> 模型 bbox          gen/artw_front.png（与岛编号图逐像素对齐）
head 带 ∩ 非皮肤（语义三分类）            → 纯红剥离图 gen/peel_front_hair.png
   再按原画像素剔除 r>g 且 r-b>14        （量化色块会把脸判成非皮肤，必须二次过滤）
掩膜内 artw 像素 → 参考裁切              gen/ref_front_hair.png（白底版 _white）
色板 top6 → 头节点提示词 + 回灌底图
```

代码：`generate.js` 的 `warpArt()` / `peelParts()`；`--only-peel` 只跑剥离 + P 组。

两个实测结论：

1. **头带主色原本是肤色**：`bandColor.head = #f9d9c4`，之前节点提示词一直在拼 `#f9d9c4 hair`（等于让模型画肤色头发）。剥离后换成 `#b7c3a5`（原画发丝主色），P 组 head 饱和度 0.178 → 0.194、细节 11084 → 11262。
2. **不能按颜色扩展到长发岛**：长发质心落在 torso/hip 带，试过用岛均色匹配头部种子色，结果披风/裙摆也是同一个浅绿，整片披风被涂成红色（误剥面积远大于长发）。所以只剥 head 带——长发本来就在脸的下方，不会和「脸」混淆，真正需要隔离的只有头带。

回灌阶段（P）把 head 区域的底图从 5 档量化色换成**抠出来的原画像素**，发丝的浅绿层次原样带回，且取色范围被岛掩膜限制，不会再参照旁边的脸和衣服。

### 5.7 ControlNet 强化矩阵（10 组）

固定同一底图 / seed / denoise，只动注入强度、第二路权重、生效步区间（`--cn-lab`，结果 `cnlab.json`）：

| 组             | 变化                  | IoU        | precision  | 边缘比       | head 细节   | torso 细节  | feet 细节 |
| ------------- | ------------------- | ---------- | ---------- | --------- | --------- | --------- | ------- |
| d90           | 基准（= CND）           | 0.8717     | 0.8744     | 0.686     | 19802     | 13788     | 30515   |
| **d100**      | depth 0.9 → **1.0** | **0.8851** | **0.8876** | **0.729** | **20017** | **14040** | 28653   |
| d110          | depth 1.1           | 0.8859     | 0.8882     | 0.725     | 19165     | 13898     | 26940   |
| d90_l35       | + lineart 0.35      | 0.8729     | 0.8745     | 0.720     | 18426     | 11183     | 24763   |
| d90_u35       | + UV 硬轮廓 0.35       | 0.8627     | 0.8644     | 0.679     | 19069     | 11863     | 19886   |
| d90_u70       | + UV 硬轮廓 0.7        | 0.8618     | 0.8628     | 0.736     | 16491     | 9947      | 16720   |
| d90_u90       | + UV 硬轮廓 0.9        | 0.8557     | 0.8566     | 0.731     | 16331     | 9219      | 16045   |
| d90_end75     | depth 只在前 75% 步生效   | 0.8618     | 0.8685     | 0.668     | 18274     | 14288     | 31657   |
| d90_end50     | depth 只在前 50% 步     | 0.8184     | 0.8395     | 0.707     | 14670     | 12383     | 31150   |
| d90_u70_end75 | UV 0.7 + 提前结束       | 0.8683     | 0.8695     | 0.732     | 17434     | 10952     | 19347   |

结论：

1. **唯一稳定收益是 depth 提权重**：0.9 → 1.0，IoU +0.013、precision +0.013、边缘比 +0.043、head 细节 +215，且 `d90` 完全复现了 CND 的 0.8717，说明矩阵本身可复现。
2. **1.1 开始过度刚性**：IoU 只再涨 0.0008，precision 微涨，但 head/feet 细节回落（19802→19165、30515→26940）。推荐 **depth 1.0** 作为新的默认。
3. **UV 硬轮廓不适合当第二路 CN**：0.35 / 0.7 / 0.9 三档全部低于基准，且权重越高细节掉得越狠（0.9 时 torso 13788→9219）。它和 depth 争同一层约束——depth 已经决定了「体量在哪」，再叠一层边界只会把采样往"死板"推。分件边界应继续留在底图（lineart / 语义线）里，不占 CN 通道。
4. **提前结束注入不划算**：end 0.75 保住甚至提高了 hip/feet 细节（15575 / 31657），但 recall 0.9964→0.9911、IoU 掉 0.010；end 0.5 直接崩到 0.818。结构必须约束到采样结束。
5. 低权重 lineart（0.35）基本中性：IoU +0.001，细节普遍略降，不值得为它付第二路的耗时。

### 5.8 论文线索与推理期一致性选择（6 候选）

检索到的三条可用线索：

1. **ControlNet++（ECCV 2024, arXiv:2404.07987）**：从生成图里反推条件，与输入条件算像素级循环一致性，再用它做 reward 微调；分割/线稿/深度分别提升 11.1% mIoU / 13.4% SSIM / 7.6% RMSE。需要训练，不能直接搬。
2. **MVPaint（CVPR 2025）**：同步多视图生成 → 空间感知 3D 修补（补没观察到的区域）→ UV 空间超分 + 接缝平滑。对应到本仓库，第一步是 bake 的 53% 覆盖率与 UV 接缝。
3. **Best-of-N + 验证器**：多采样后用 reward/verifier 选优，是推理期最便宜的扩展方式。

免训练落地：**depth 1.0 + 6 个 seed，验证器 = `0.7*IoU + 0.3*min(1,edgeRatio)`**（`--pick 6`）：

| seed | 验证分 | IoU | head 细节 | feet 细节 |
|---|---|---|---|---|
| **20365842（被选中）** | **0.8515** | 0.8778 | 13323 | 10714 |
| 20261113 | 0.8383 | **0.8851** | **20017** | **28653** |
| 20575300 | 0.8368 | 0.8865 | 15538 | 13234 |
| 20784758 | 0.8367 | 0.8747 | 16821 | 9799 |
| 20680029 | 0.8210 | 0.8669 | 18122 | 11433 |
| 20470571 | 0.8206 | 0.8735 | 12008 | 11378 |

结论：

- seed 间方差很大：IoU 0.867~0.887，head 细节 12k~20k。**只靠轮廓/边缘一致性选出来的图，细节可能最差**（选中的 20365842 head 只有 13323）。
- 本轮 20261113 恰好同时是 IoU 和细节最好的，所以 best-of-6 相对「调优过的 seed」没有增益；相对 6 个 seed 的均值（IoU 0.877）也只 +0.008。**要选细节，验证器里必须有细节项**，光靠 ControlNet++ 式结构一致性不够。
- 真正有增量的方向不在采样选择，而在 ①MVPaint 式 UV 空间精修（当前覆盖率 53%）、②更高分辨率二段生成。两项都未实施。

读法：

- **开环 → 闭环**：BL 0.784 → CNL 0.805 → CND 0.872。depth 比 lineart 更管用，因为它约束的是「体量占多大、在哪」，而 lineart 只约束「边界在哪」；两者叠加（CNLD）反而不如单 depth，说明 0.85 的 lineart 权重在抢 depth 的活。
- **recall 全部拉到 0.997 以上**：闭环基本消灭了「漏画某一块」，剩下的误差全是「画出去一点」（precision 0.81~0.87）。
- **细节**：CND 最高（head 19802、feet 30515），因为深度图给了明确的体积层次，SD 会把褶皱和分件画满。
- **代价**：CN 单张 12~~20s（lineart 条件图是 1:1 尺寸，depth 也是），比 img2img 贵 2~~3 倍；D 28s 最贵。
- **配色**：D 的饱和度最低（0.178），因为色相全部取自原画（原画本身低饱和）；CN 组的高饱和绿发是 checkpoint 的默认倾向。


- **UV 硬轮廓（CNU）单独用不如线稿/depth**：它只有分件边界、没有体量线索，IoU 0.816；但它是唯一能画出「头发 / 脸 / 衣服」分界的条件。和 depth 一起用（CNUD）就到 0.857，离最好的 CND 只差 0.014——**分件边界换 0.014 IoU 是划算的**，因为它保的是「发不糊进脸」。
- **CNUS / CNUDS 说明一件事**：把部件词按掩膜叠加进同一次采样，收益为负（细节掉 20%~~40%，耗时涨 2~~5 倍）。语义强化应该放在生成后（D 的节点级联），不是塞进同一次采样。

## 7. 反投（UV 烘焙）

`MVProject.runImage` + `TexPaint.bakeProject`，4 视图、1024 格、gap 0、正交相机、inset 1、fill 15：

| 组  | 覆盖率 | 已烘焙 texel             | UV 岛 | 丢岛  | 2048 贴图耗时 |
| -- | --- | --------------------- | ---- | --- | --------- |
| BL | 53% | 1,642,101 / 3,109,435 | 2491 | 303 | 7.9s      |
| D  | 53% | 1,642,101 / 3,109,435 | 2491 | 303 | 8.4s      |

两组覆盖率**完全一致**，说明 53% / 303 个丢岛是**几何决定**的（4 个正交视角看不到的岛：袖筒内侧、裙摆背面、发束背面），与生成图无关。

差别在侧面/背面：BL 三视图各自独立生成，正面绿发、背面被画成粉紫裙，反投后左右后三视图明显色偏；D 因为配色来自跨视图共享的语义底图，四视图色调一致但整体偏平。**跨视图一致性靠单张生成保证不了，必须有共享的配色来源**——这是 UV 岛语义分区真正的价值。

背视图还会犯另一个错：底图取色把后脑勺的岛投回原画脸上，于是背面被画出一张脸。修法分两层（§5.3 第 5 条）：底图只让 front 真见过的岛继承 front 的颜色，front 没见过的 head 带岛继承头发色；节点提示词按视角切换（背面 `back view of the head … no face` + 负面词 `face/eyes/nose/mouth`）。复跑后 `D_back` 的后脑勺已是头发，正面五官不受影响。

## 9. 已知问题

1. **A 不是严格下限**：checkpoint 对角色有强记忆，纯文本会画出同一角色（还带森林背景），A 的低 IoU 主要来自构图自由。
2. **SD1.5 + 512²** 是当前瓶颈：节点级裁切喂的是 4K，出图仍是 512²，贴回要放大；换 SDXL/Flux 后上限更高。
3. **D 偏平**：底图是纯色块，denoise 0.40 不足以补出布料质感；节点补回的细节又被「语义配色回灌」按亮度比压平（head 细节从 14623 掉到 11084）。下一步应把回灌从「逐像素亮度比」改成「只回灌色相/低饱和色差」。
4. **CNLD 叠反了**：lineart 0.85 + depth 0.55 不如单 depth，下一轮应先扫 depth 权重（0.9→1.0）再决定是否叠加。
5. **覆盖率 53%**：需要针对 bake 的视角数量 / fill 门槛做一轮参数扫描，本次未做。
6. **UV 硬轮廓条件图仍有碎点**：语义三分类用的是量化后的岛色，相邻量化档不同会在裙摆/披风上产生孤立边界点；阈值和小面积过滤还没调。
7. **同一次采样里的部件词叠加无效**：`ConditioningSetMask` 只加权重不移除全局词，语义部位必须靠生成后的节点级联。
8. **部位剥离只覆盖 head 带**：长发岛的质心落在 torso/hip 带，按岛色向外扩展会把同色披风/裙摆一起剥进来（实测误剥面积远大于长发）。要完整剥离需要 3D 岛邻接连通性，当前未做。
